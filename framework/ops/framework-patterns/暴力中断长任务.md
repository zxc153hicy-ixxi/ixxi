# 暴力中断长任务

## 发生了什么

搭建长耗时任务工具（如视频转录、批量处理）时，最初的停止方案是让用户 `Ctrl+C` 中断 + `KeyboardInterrupt` 捕获保存断点。但用户指出「冒然中断不会出问题吗」——暴露了把信号中断当作"正常停止方式"的问题：

- 中断时机不可控：可能正好在文件写入中途 → 数据损坏
- 部分平台（如 Windows）上信号行为不可靠
- 用户操作门槛高（需要知道 `Ctrl+C`、找对终端窗口）

## 根因

训练数据中大量使用 `try/except KeyboardInterrupt` 模式，形成惯性思维——把应急手段当常规操作。

## 正确做法

改为**信号文件/优雅中断机制**：
1. 用户对系统说「暂停」→ 创建标记文件
2. 任务在安全检查点检测标记 → 保存 checkpoint → 优雅退出
3. 用户说「继续」→ 从断点续传（--resume）

## 识别特征

- 提议"Ctrl+C 就行"、"kill 进程即可"作为长任务的停止方案
- 任务的上下文有价值（处理进度、已处理数据），中断后需要恢复
- 用户不是技术人员，不熟悉终端操作
