# 验证绕过挂载点

## 现象

验证 hook、事件触发、自动调度这类「挂载型」机制时，用命令直接跑目标脚本文件（如直接运行 hook 目录下的 pre-commit 脚本），绕过了真实的挂载路径（git 实际调用的 `.git/hooks/pre-commit`）。

## 后果

验证显示「通过」，但真实触发时机制根本没生效——机制「挂对位置但没生效」。

## 实例

某 pre-commit hook 挂载到了扩展 hook 目录，但 git 实际调用的是 `.git/hooks/pre-commit`（独立的旧文件）。测试时直接运行扩展目录里那个文件，验证「通过」；真实 commit 走 `.git/hooks`，该 hook 的检查从来没跑过。

## 根因

「挂载位置」本身就是最容易被验证方式绕过的环节——验证「机制逻辑对不对」（直接运行目标文件）不等于验证「机制有没有被触发」（真实触发走到它）。这是「机制正确 ≠ 机制有效」在挂载型机制上的体现。

## 正确做法

验证「挂载型」机制，必须**真实触发**：

- hook → 真 commit（看 hook 是否真的被调用）
- 事件触发 → 真实触发事件
- 自动调度 → 真实走一遍调度流程

不能直接运行目标文件——那验证的是「脚本本身」，不是「挂载是否生效」。
