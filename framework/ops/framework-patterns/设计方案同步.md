# 设计方案同步

修改系统规则后，自动提醒同步更新对应的设计方案文档，防止设计与实现漂移。

## 触发
顶层规则、路由层、细则文件、新机制、目录结构变更时，同步检查设计方案是否仍需更新。

## 核心原则
- 设计文档是系统的「为什么」，实现是「是什么」，两者必须同源
- 任何规则/机制/结构的变更都要连带核对设计文档
- 把「同步设计」变成变更流程的固定步骤，而不是事后想起

## 为什么有效
- 设计文档一旦滞后，后续实现会被旧设计误导
- 变更时顺手更新是零成本，事后补对齐需要重新审计
