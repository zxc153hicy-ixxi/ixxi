# 架构变更联动检查

## 什么做法
架构级变更完成后，不满足于目标修复确认，主动扫描关联子系统：

1. 列出所有引用被变更路径/组件的文件
2. 对每个引用点做可用性验证（脚本可运行、路径可访问、配置可解析）
3. 发现断裂→当场修复，不另开任务

## 为什么有效
本案例中 skill 目录去重后，导出系统的两个脚本因引用过期的旧路径而预检失败。如果去重完成后立即跑联动检查，会当场发现而不是等到用户主动问"导出"才发现。

## 什么时候用
- 目录结构变更（新建/删除/移动/重命名目录）
- 配置文件路径变更
- 全局规则修改（会影响全局行为）
- 插件/hook 注册变更
