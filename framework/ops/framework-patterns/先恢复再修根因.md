# 先恢复再修根因

## 场景

自动化修复脚本批量写坏了文件（如 YAML frontmatter 损坏、内容丢失），需要既恢复文件又阻止问题复现。

## 做法

```
1. git checkout 恢复所有受影响文件（回到安全状态）
2. 定位根因——哪个函数、哪行代码导致破坏
3. 修复根因——不是修文件，是修脚本
4. python -m py_compile 验证语法
5. 重新运行修复脚本
6. 跑关联检查验证无新破坏（如 check-frontmatter.py）
```

## 案例

`fix_broken_paragraphs` 把 YAML frontmatter 合并成单行→250 文件损坏。

1. `git checkout HEAD -- knowledge/learning/` 恢复所有文件
2. 定位到 `fix_broken_paragraphs` 的 `flush_buffer()` 会 `' '.join` 合并 YAML 行
3. 加 frontmatter 边界检测（`---` 间的行原样保留）
4. `py_compile` 语法通过
5. 重跑 `--fix`
6. `check-frontmatter.py` 验证 547/547 通过

## 关键点

- **第一步永远是恢复**：先让文件回到安全状态，不急修根因
- **修脚本不修文件**：250 个文件的手动修复不可行，必须修自动化工具
- **修复后必须验证**：跑关联检查脚本，不能只看"好像好了"
