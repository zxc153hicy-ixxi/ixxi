# 审查表面化

## 现象

收到"全面审查"任务 → 跑了全部自动化检查脚本 → 统计几个数字 → 写报告声称"审查完成"。检查体系中标记为需 LLM 判断的项（占全部的近三分之一）全部跳过。

## 后果

- 遗漏率高（本次该判断项只做了 3 个，漏 15 个）
- 只发现机械问题（断链、格式），漏掉语义问题（过时文档、矛盾声明、缺失引用）
- 用户拿到报告以为系统健康，实则隐患未暴露

## 与"检查偷懒"的区别

| | 检查偷懒 | 审查表面化 |
|------|------|------|
| 行为 | 用目录列表代替递归搜索 | 跑脚本代替逐文件细读 |
| 范围 | 目录排查 | 全面审查 |
| 跳过的是 | 子目录文件 | LLM 判断项（语义理解） |

## 纠正

1. 审查前先确认：哪些是脚本项、哪些是 LLM 判断项、哪些是人工项
2. LLM 判断项必须逐项打开文件、阅读、判断、记录，不可汇总统计替代
3. 审查报告标注每项判断项的实际覆盖情况（已覆盖/跳过/跳过原因）
4. 不确定时主动问"要不要补一轮深度审查"
