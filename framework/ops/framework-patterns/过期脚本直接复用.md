# 过期脚本直接复用

> 反模式 = 踩过的坑。

## 发生了什么

用户说"调用预置流程进行修复"，直接找到旧版本时代的批量修复脚本（引用已废弃的旧目录结构路径），差点直接跑。该脚本全部引用旧版本路径，当前目录结构已不含这些路径，所有步骤全部过时。直接跑 = 全部失败 + 浪费时间 + 可能误伤。

## 根因

- 脚本文件名和描述未标注适用版本
- 没有「执行前先验证路径存在性」的前置检查
- 先执行后思考（直接跑流程 vs 先检查是否匹配当前状态）
- 用户指令"调用预置流程"听起来像标准流程，实际流程已过时

## 怎么防

- 脚本/工作流头部标注适用版本号和前提条件（如 `# requires: V4.x, ops/ + knowledge/ structure`）
- 执行旧脚本前先跑前置检查（路径存在性、目录结构匹配）
- 设计先行：即使是"复用已有脚本"，也要先确认是否适用当前结构
