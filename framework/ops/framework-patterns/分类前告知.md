# 分类前告知方案与后果

## 模式
涉及文件结构变更时，不直接动手，先展示：
1. 当前状态
2. 建议方案
3. 优劣对比
4. 后果评估（无数据丢失、链接断裂风险等）

用户确认后再执行。结构变更属于破坏性操作，应当固化为默认流程而非临时决定。

## 为什么有效
- 结构变更影响面广、难回滚，先看后果再动手，避免一次性重构带来隐性破坏
- 优劣对比让用户做知情选择，而不是被动接受
- 显式声明"无数据丢失、链接断裂风险"等约束，把风险写进决策
