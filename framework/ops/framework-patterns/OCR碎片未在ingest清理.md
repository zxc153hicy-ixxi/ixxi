# OCR 碎片未在导入阶段清理

## 问题

MinerU 等 OCR 工具转换 PDF 后会残留大量图片碎片文件（`_page_X_Picture_Y.jpeg`）和 markdown 中的 `![]()` 图片引用。这些碎片在知识库/笔记软件中显示为空白框，严重干扰阅读体验。

典型规模：一次批量转换残留上千个 JPEG 碎片文件、数十个 md 文件中上万行 `![]()` 引用，全部是 OCR 页面布局碎片。

## 为什么是反模式

- 事后批量清理成本高（需全量搜索 + 脚本处理 + 验证）
- 碎片文件占用磁盘空间
- 图谱/关联视图被污染

## 正确做法

在导入流程的「转换后」阶段增加清理步骤：删除 `_page_*_Picture_*.jpeg` 等 OCR 碎片图片，并从 md 文件中清除 `![](_page_*` 引用。

原则：**管线产生的垃圾要在管线内清除**——转换产物进入下游之前完成清理，而不是等垃圾已经扩散到正式内容区后再批量返工。

## 通用启示

- 任何「转换/解析」类工具链，都要在转换后立即检查是否有可丢弃的中间产物（碎片图、临时文件、标记引用），并把清理编入导入流程的标准步骤。
- 清理时机越早，成本越低：事后批量清理的成本通常是流程内清理的数十倍。
