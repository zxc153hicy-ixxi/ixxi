# 信号文件优雅中断

## 什么做法

需要长时间运行的后台任务（如视频转录、批量处理），不使用 `kill`/`Ctrl+C` 等信号暴力终止，而是：

1. LLM 创建一个标记文件（如固定路径的暂停标记）
2. 脚本在主循环中定期检查该文件是否存在
3. 检测到标记 → 保存当前进度（checkpoint）→ 删除标记文件 → 优雅退出
4. 下次运行 `--resume` 从断点处继续

## 为什么有效

- **kill/Ctrl+C 的问题**：可能中断在文件写入中途 → 数据损坏；不保证触发清理逻辑 → 临时文件残留；部分平台上信号行为不可靠
- **信号文件**：脚本自己控制退出时机（在安全的检查点），100% 确保 checkpoint 保存完成后再退出；跨平台一致；外部可编程控制（写文件即可）
- **丢失上限可控**：检查间隔即最大丢失量（如每 30s 检查一次，最多丢 30s 进度）

## 什么时候用

- 长时间任务（> 5 分钟），用户可能需要中途暂停
- 批量处理需要支持"做到一半先停"的场景
- 需要跨会话恢复的异步任务
- 替代场景：任务 < 1 分钟 → 直接等；纯云端 API 调用 → 不需要

## 实现要点

1. 标记文件放在固定路径，外部控制和脚本都能访问
2. 检查时机：嵌在主循环的自然断点处（如每处理 N 条记录后）
3. 退出前：保存 checkpoint + 清理标记文件 + 更新全局状态
4. 退出码：正常暂停用非错误退出码（区别于错误退出）
5. 外部职责：创建标记文件后通知用户「已发送暂停信号，脚本将在下一个检查点自动退出」
