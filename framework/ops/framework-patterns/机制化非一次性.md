# 机制化非一次性

用户提"减负""清理"等需求时，不直接手动删除文件，而是构建可复用的自动化机制。机制包含三个层次：检测（自动发现）→提醒（主动告知）→执行（一键操作）。

## 核心原则

1. 机制优先于操作——先建工具再做具体清理
2. 配置驱动——不同场景通过配置文件差异化，不硬编码
3. 集成到现有流程——不另起炉灶，嵌入已有工作流（如 Ingest）
4. 安全分层——默认 dry-run、执行前确认、git 守护、操作日志

## 修复场景：修复即建护栏

修复一个问题类时，必须同时建一个自动化护栏（脚本检测），防止同类问题复发。这是机制化在「修复」场景的应用——不满足于「修好了这一个」，而是「建护栏防住这一类」。

## 分类场景：写入时分类

分类/登记这类需要「判断」的东西，做成写入时的机制（frontmatter 字段 + hook 强制），而不是事后一次性盘点。例：正反模式 scope 字段——写入时当场判「不涉隐私 AND 绝大部分人有用」，hook 强制 scope 必填 + 目录一致，新条目自动分流，不再回到手动盘点。

## 适用信号

- 用户说"定期""经常要""每次都要"
- 同类操作已手动执行过 ≥2 次
- 操作有规律可编程化

## 反例

> 用户说"删掉旧版本"→LLM 手动 rm 一个文件→下次又来了→再手动删→第 N 次用户问"能不能自动化"
