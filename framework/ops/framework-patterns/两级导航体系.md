# 两级导航体系

## 问题

知识库初期使用单一 `index.md` 作为全局 MOC，直接链接 100+ 个文件。结果：
- 关系图谱呈星型拓扑（一个中心节点 + N 个孤立叶子）
- 浏览时需要在超长列表中翻找
- 同一目录下的文件缺少聚合入口

## 做法

每个主目录配一个中文描述名的索引页，形成两级结构：

```
index.md（全局 MOC）
  ├── ops/anti-patterns/反模式索引.md（18 条）
  ├── ops/patterns/正模式索引.md（19 条）
  ├── knowledge/projects/知识库管理/iterations/迭代记录索引.md
  ├── knowledge/projects/知识库管理/queries/查询报告索引.md
  ├── knowledge/archive/归档内容索引.md
  └── raw/sessions/会话摘要索引.md
```

每个索引页包含：
- 目录内所有文件列表
- 每个文件的一句话描述
- 指向相关索引页的交叉引用

## 效果

- 全局 MOC 从 100+ 行缩减到 ~80 行
- 关系图谱从单层星型变为两级树型
- 每个目录有独立入口，可独立浏览
- 索引页本身有描述名，看文件名即知内容

## 复用条件

- 目录内文件数 >10 时考虑建索引页
- 索引页命名 = 目录名 + 描述（如 `反模式索引`、`创作内容索引`）
- 全局 MOC 只链接索引页 + 高频文件，不逐条列出
