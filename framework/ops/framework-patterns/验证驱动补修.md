# 验证驱动补修

> 正模式 = 验证有效的做法。

## 是什么

声明"完成"之前，先跑一轮全量验证（路径审计、数字一致性、frontmatter 完整性、回归扫描），验证发现的遗留问题当场修复，不另开 Issue 或新任务。

## 为什么有效

- **验证是最后一道防线**：7 个 Phase 经 14 个 agent 完成，Phase 7 验证仍发现 3 处不一致（健康度公式 14→18、R层 22→24、正模式 26→27）
- **当场修 zero-cost**：验证 agent 直接输出具体行号和修复方案，当场 Edit 即可，不开新任务零上下文切换
- **防止逐步漂移**：不验证直接声明完成 → 下次会话发现不一致 → 需要重新审计 → 浪费时间
- **符合 G14 闭环理念**：和会话结束前反馈收集一样，修复结束前验证是质量闭环

## 什么时候用

- 任何多文件批量修复结束后
- 版本升级后的一致性检查
- 计数/路径/公式等跨文件引用的修改后
- 每个 `/audit` 后应跟一次验证
