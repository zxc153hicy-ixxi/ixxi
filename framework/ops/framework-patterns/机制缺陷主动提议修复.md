# 机制缺陷主动提议修复

## 场景

使用机制的过程中（加载框架、跑流水线、执行 skill）发现机制本身有缺陷或遗漏——该做的没做、该加载的没加载、流程断层、护栏失效。

## 正确做法

1. **发现即提**：一旦发现机制缺陷，当场主动提议修复，不等用户自己撞见才处理
2. **提议带方案**：说清「缺陷是什么 + 影响范围 + 修复方案」，走确认流程（G12）
3. **改后复验**：修复完成后实测验证（改了什么就复验什么），不声明未验证的完成

## 反例

kb-load 加载流程只覆盖框架层 6 步，漏了 G8 启动加载（画像/操作菜单/正反索引/queue/session-notes）。LLM 加载时没主动发现，直到用户追问「用户画像没加载吗」「正反也该加载吧」才暴露——机制缺陷被动等用户发现，已让用户踩了「加载不完整」的坑。
