# 真实生效验证

「完成」的标准是「真实生效」，不是「做完了」。任何产出——设计、代码、机制、知识、修复——都要用「它真实生效了吗」来验收，不是「我做完了吗」。

## 三个维度

### 1. 假阴性自检

检查脚本要证明「它真的在查」——输出含「扫描了 N 个文件」，N==0 报警。凡「输出通过但可能空查」的都要查。

实例：检查脚本遍历已删除目录，报错被吞、输出 ALL_OK；扣分制 `10 - len//3` 让 1-2 处问题不 fail；过滤命令误伤名字匹配的文件；编码不一致导致匹配不到。

### 2. 机制有效性验收

机制正确（脚本算对）≠ 机制有效（真防住）。验收标准是「违规被阻止」，不是「问题被检测」。配红队测试：故意违规，看机制拦不拦。

实例：机制检测到违规却不阻止（正确但没防住）；钩子挂到错误位置，真实事件没走到它（挂对位置但没生效）。

### 3. 黄金标准验证

用人工审计核实的正确值当锚，脚本输出对不上就是脚本错，不存在「对错靠感觉」。

实例：计数类校验用人工审计核实的值当锚，脚本输出对不上就是脚本错。

## 核心原则

- 自检要证明自己在干活：空查即报错，防止「ALL_OK」掩盖「根本没跑」
- 机制验收看结果不看过程：防住才算数
- 用黄金标准锚定正确性，消灭「对错靠感觉」
