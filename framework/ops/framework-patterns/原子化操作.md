# 原子化操作

> 正模式 = 验证有效的做法。

## 是什么

将对文件的操作设计为原子单元——主操作（创建/重命名/删除）和所有关联步骤（更新索引、替换引用、重排编号、更新计数）内聚为一步，不可拆分。要么全做完，要么全不做。

不是靠"记得检查"来防漏，而是让操作本身在物理上不可能遗漏。

## 为什么有效

- **消除人类记忆依赖**：不需要记住"改完 A 还要改 B 和 C"，脚本自动完成全部关联步骤
- **事务性保证**：失败自动回滚，不留半成品
- **零扩展风险**：插件目录模式，新增操作不碰已有脚本
- **LLM 友好**：统一入口 + 自动发现 + 无交互设计

## 什么时候用

- 操作涉及 ≥2 个关联文件（如创建文件 + 更新索引）
- 操作步骤中有"别忘了"类提醒——说明这个操作应该原子化
- 同类手动操作已执行 ≥6 次——提醒封装为 action
- 操作涉及 ≥9 个文件的纯机械步骤——提醒封装为 action
