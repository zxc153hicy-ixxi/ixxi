# enrich 试点→修正→批量模式

## 场景

对大量文章进行元数据富化（打标签、写摘要）时，LLM 对领域标签的判断可能与用户预期不一致。

## 做法

1. 先选 3 个领域各 5 篇试点
2. 展示完整结果（文件、建议 tags、建议 summary、置信度）给用户审核
3. 用户反馈修正规则（如"真题/押题统一""SD-WAN 归广域网""按题目内容归大类"）
4. 修正后全量批量推进

## 为什么有效

- 批量偏差在 15 篇阶段暴露，修复成本低
- 用户确认的规则可以固化为 agent prompt，减少后续偏差
- 试点也是给用户的信心锚——看到质量再放行
