# 审查驱动

实现阶段每个 task 经过两轮独立审查：spec compliance（核对是否按规格实现）→ code quality（核对代码质量），两轮都通过才进入下一 task。审查者独立读代码，不信任实施者的自述。

## 核心原则

1. 实施者完成后自审，报告 status（DONE/DONE_WITH_CONCERNS/BLOCKED）
2. spec reviewer 读代码逐条核对需求，标注缺失/多余
3. code quality reviewer 检查逻辑错误、边界情况、代码质量
4. 任一审查发现问题→修复→重新审查，直到通过
5. 先 spec 后 quality，顺序不可颠倒

## 关键收益

- YAML 解析器 bug（无法解析列表/嵌套字典）在审查阶段被发现，未进入生产
- 排序逻辑错误（格式码排到版本号前面）在审查阶段暴露

## 反例

> 实施者写完说"DONE"，LLM 直接 commit→运行→报错→才发现基础功能有bug
