# 混用路径格式

## 现象

在 Git Bash 里写 `work_dir = "/d/xxx"` 给 Windows 原生程序，程序启动后无法识别路径，报"启动失败"。

## 根因

Git Bash 通过 MSYS2 的路径转换层自动把 `/d/xxx` 映射为 `D:\xxx`，这让编辑器里的路径在 Bash 命令中能正常工作。但**目标程序不经过 Bash**——Windows 原生程序对 `/d/xxx` 来说是一个不存在的相对路径。

本质：**为某个程序写配置时，路径格式必须匹配该程序的运行环境，而非当前编辑环境。**

## 正确做法

1. 写配置前确认目标程序的运行环境（原生 Windows / MSYS2 / WSL / 容器）
2. Windows 原生 → `D:\xxx`（TOML 中写 `D:\\xxx`）
3. Git Bash / MSYS2 内部 → 可用 `/d/xxx`
4. WSL → `/mnt/d/xxx`
5. 不确定时用绝对 Windows 路径最安全
