# LLM 兜底脚本

## 场景
自动检查脚本能发现机械问题（空文件、无标题、死图片），但无法判断"这个问题是否真的需要修"——索引页就该小、OCR 乱码可能可读。语义判断需要 LLM。

## 做法
三层协作：

```
脚本 → LLM → 脚本收敛

1. 脚本机械扫描 → 标记 quality_issues 字段
2. LLM 审查标记文件 → 判断：真问题/可接受/需人工
3. 脚本收敛 → is_llm_reviewed() 检查 → 无 quality_issues = 已审查 → 跳过
```

## 案例
`check-ocr-quality.py` 扫描 395 篇资料，标记 292 篇有问题（死图引用、空壳、无标题）。

脚本修复（死图删除 + 段落合并）→ 剩 8 篇标记文件。

LLM 逐篇判断：
- 4 个"空壳"→ 索引页，设计如此 → 清除 quality_issues
- 2 个"无标题"→ 补 `# 标题`
- 1 个"乱码"→ 内容完全不可读 → 标记 `status: degraded`
- 1 个"乱码"→ OCR 质量低但可读 → 保留标记

结果：8 → 2（仅剩无法修复的 OCR 质量问题）

## 关键点
- **脚本不打分不删除**：只标记 `quality_issues`，不做不可逆操作
- **LLM 审查标记就是终局**：`is_llm_reviewed()` 检测到文件被审查过，不再重复报警
- **检查体系尊重审查结果**：LLM 审查通过的文件不扣分
