# 排查未锚定主线

## 发生了什么

一次提交被校验钩子拦停，排查「设计文档在哪」时：
1. 先信项目日志里记录的旧路径（文档曾位于旧目录），认定设计文档在旧位置，还提议把文件搬迁过去
2. 用户纠正「已迁移到新目录」后找到了新目录，但没锚定「当前任务主线是什么」，在两个相似设计文档（通用版与专项版）之间反复混淆
3. 用户连续纠正 3 次，最后查版本历史才定位到真实位置

## 根因

排查时优先信了历史记录而非实测，且没在排查第一步锚定「当前任务主线是什么」。旧记录早已过时（文档已迁移），但没先实测就直接采信；主线与排查对象是两件事，没区分导致反复绕。

## 怎么修

1. 排查路径/位置类问题时，先实测（递归查找/列目录）再下结论，不先信文档里写的旧路径
2. 排查第一步先锚定「当前任务主线是什么」，判断排查对象与主线的关系，避免被无关概念带偏
3. 涉及「文档迁移过」的资源，先查版本历史确认最新位置，而非信日志/索引里的过时记录
4. 用户纠正一次后，立刻停下重读原始诉求 + 当前主线，别在同一错误方向继续打转
