# 原子级拆解教学

## 做法

碎片化场景（如手机阅读）或入门教学时教新知识，按四条规则拆到不能再拆：

1. **名词必解释**：每个专业术语（如 SQL 中的 SELECT、WHERE、AND、引号闭合）必须给出定义，不许假设用户已经知道
2. **操作必说 why**：为什么输入 `' OR '1'='1` 而不是 `OR 1=1`？因为第一个 `'` 是为了闭合前面的开引号——把这个逻辑链完整展示
3. **不跳前置**：用户说了"从基础开始"，就不能默认他懂数据库、懂逻辑判断、懂三目运算。先讲数据库是什么，再讲 SQL 是什么，最后才讲到注入
4. **一段一概念**：每条消息只讲一个核心概念，收尾确认理解再继续

## 为什么有效

- 碎片化场景屏幕小、注意力分散——长文直接被跳过
- 安全/技术知识有大量前置依赖——跳过一个没解释的概念，后面全听不懂
- 用户没说你懂就是不懂，不要假设用户有前置知识

## 什么时候用

- 用户在碎片化场景问学习类问题
- 用户说"基础""入门""从零开始""小白"
- 用户反馈"解释不够清楚""你假设我懂了"

## 反例

- "SQL 注入就是在输入框塞 SQL 代码"——没说为什么能塞进去，没解释引号闭合
- "用 sqlmap 跑一下就行"——跳到工具，用户连 SQL 是什么都不知道
