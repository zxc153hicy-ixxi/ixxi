# 工具建成即登记

> 正模式 = 验证有效的做法：写完工具脚本后，必须在知识库导航中登记入口。

## 是什么

新建或合并 `framework/engine/scripts/` 下的工具脚本后，立即更新两份文档：
1. **`activation.md`** — 更新脚本数量和名称列表
2. **`personal/index.md`** — 在 `framework/engine/scripts/` 区域添加入口链接

## 为什么有效

- **反模式教训**：本次会话中合并了 3 个脚本（check_stale / check_links / check-inbox），建完就跑通验证，但忘记登记。结果 activation.md 仍写着"auto-import.py + cleanup-versions.py（2 个脚本）"，实际已有 15 个。G18 要求「工具优先」，但工具不可发现等于不存在。
- **G18 闭环**：工具优先不只是写脚本，还包括让后续 Agent 能找到脚本。登记是实现 G18 的最后一步。

## 什么时候用

| 触发条件 | 动作 |
|------|------|
| 新建脚本（如 check-xxx.py） | 更新 activation.md 计数 + personal/index.md 入口 |
| 合并/删除脚本 | 同步更新两份文档的计数和列表 |
| `/check` 体检 | E8（脚本无功能重叠）检测到碎片化时，合并后走本流程登记 |

## 登记清单

- [ ] `activation.md`：`framework/engine/scripts/` 行更新脚本数量和分类
- [ ] `personal/index.md`：`framework/engine/scripts/` 区域新增入口（至少列出高频脚本）
- [ ] `framework/ops/rules/知识库检查体系.md`：附录脚本总览表同步
- [ ] `framework/ops/hermes/Hermes-命令索引.md`：如有 `/lint` 链变化需同步
