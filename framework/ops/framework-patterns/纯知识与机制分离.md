# 纯知识与机制分离

## 场景
迁移知识库到 ixxi 时，原库顶层机制（ops/engine/.claude）与知识（knowledge）平级混放，机制散在 4 处，一眼分不清「这是知识」还是「跑知识的机器」。

## 为什么有效
- 纯知识（内容资产）、系统机制（帮你跑知识的东西）、运行数据（使用痕迹）是三个性质完全不同的东西，混放造成认知负担
- 三区分离（knowledge/system/data）让「这是我的内容」和「这是机制」一眼可辨
- 分层的判据清晰：知识 = 内容，机制 = 帮内容跑起来，数据 = 使用产生的痕迹

## 操作方式
1. 迁移/重构目录时，先问「这是内容、机制、还是数据」三分类
2. 知识 → knowledge/（学习、项目、归档）；机制 → system/（skill、规则、脚本）；数据 → data/（反馈、会话、记忆）
3. 框架通用层（framework）与个人实例层（personal）也按同一判据分——机制开源进 framework，内容私有进 personal

## 效果
- 本次迁移用三区分离落地，personal 1569 文件清晰分为 knowledge 550 / system 879 / data 138
