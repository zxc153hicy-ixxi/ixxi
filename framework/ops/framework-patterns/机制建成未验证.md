# 机制建成未验证

## 发生了什么

一条「自动调度」机制落地：文档完备、设计精良（映射表 + 三步调度 + 多档优先级），但一个月后触发计数为 0、一次都没触发，无人察觉。多重根因叠加：

1. **二级嵌套不可见**：内部工具/脚本放在扩展系统目录的二级子目录，框架只扫描一级目录、不递归 → 全部不可见
2. **跨执行者悬空引用**：规则在共享层说明文档要求「匹配调度映射表」，但映射表写在某执行者专属层 → 其他执行者读到规则却找不到表
3. **无自动化兜底**：调度全凭自觉，计数靠自觉记账，无任何钩子强制或检测

## 根因

「文档写完、规则落地」被当成了「机制生效」。缺一个可观测的触发指标 + 首触发验证环节——机制上线后没人问一句「它真的被触发了吗？」。

## 怎么修

1. 建成任何「自动」机制后，设一个可观测指标（计数/日志/列表出现），并在下一会话验证它真的增长/出现
2. 涉及「发现/加载」的机制，先实测目标对象真的能被发现（如工具出现在可用列表），再宣称完成
3. 跨执行者共享资源时，确认引用目标在「共享层」而非「某执行者专属层」
4. 语义判断靠执行者、机械兜底靠钩子——纯自觉的机制必然失守，至少补一条机械检测
