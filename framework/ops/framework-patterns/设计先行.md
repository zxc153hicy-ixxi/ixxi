# 设计先行

先设计再动手，禁止拿到需求直接写代码。

## 适用场景

- **功能开发**：走 brainstorming→spec→plan→implement 完整流程（适合中等及以上复杂度：≥3 个新建/修改文件、涉及架构选择、需求未完全明确）
- **复杂改动**（知识库运维）：先写设计文档→架构方案→实施文档，写清楚再动手

## 核心原则

1. brainstorming 阶段只讨论不落笔，逐条确认需求
2. spec 是用户与实现之间的合同，写完必须用户审阅
3. plan 是给执行者的施工图，每步 2-5 分钟粒度
4. implement 走 subagent-driven，每 task 经两轮审查
5. 复杂改动场景：设计文档暴露根因、实施文档让用户提前审核改动范围、优先级排序避免「什么都想做但什么都没做完」

## 适用信号

- 用户说"设计一个机制""我要一个系统"
- 涉及新建多个文件
- 有多种合理实现方式可选
- 前一次实现被用户否决（说明需求未对齐）

## 反例

> 用户说"帮我写个清理脚本"→LLM 直接新建 cleanup.py 开始写→写到一半用户说不对→重写→再不对→用户说"算了先设计一下"
