# 结束对话知识沉淀

## 什么做法

对话结束时不只收集反馈，额外增加一个**知识沉淀环节**：

1. 回溯对话中产生的**新知识/新流程**（不是已有规则的重复）
2. 逐条列出，问用户「要不要写进知识库？」
3. 用户确认后写入对应目录
4. 更新相关索引

## 为什么有效

- G13（结束检查）只覆盖了反馈收集，没有覆盖「新产生的知识是否需要入库」
- 一次长对话可能产出大量可复用内容（技术选型、操作流程、决策框架），不主动提议就会被遗忘
- 逐条确认而非笼统问「要不要入库」，提高沉淀率

## 沉淀类型与落点

| 内容类型 | 落点 | 示例 |
|------|------|------|
| 新技术选型/调研 | `personal/knowledge/projects/<领域>/` | AI注入技术全景、ATS市场分析 |
| 新操作流程 | `personal/system/patterns/` | 简历构建全流程 |
| 规则补充 | `personal/system/patterns/` 或更新G层 | 结束对话知识沉淀（本条） |
| 差评/好评 | `personal/data/feedback/` | 已有G2覆盖 |

## 结束对话完整清单

```
[ ] 回溯对话，列出本次产出的新知识/新流程
[ ] 逐条问用户是否入库
[ ] 确认的→写入对应目录+更新索引
[ ] 收集反馈（G2/G13已有的）
[ ] 写会话摘要到 personal/data/sessions/
[ ] 更新会话摘要索引
```
