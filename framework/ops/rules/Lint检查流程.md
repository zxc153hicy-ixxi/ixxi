# Lint检查流程

## 约束

1. `/lint` 已统一到 `/check` 体系，兼容路由见下表
2. `/lint --full` → `/check`（自动化全量 55 项）
3. `/lint` → `/check --quick`（快速检查变更影响维度）
4. 冷启动前 5 次用固定阈值，之后切换动态基线
5. 体检报告必须包含：新增问题/持续未修复/已修复/统计快照 四段
6. **修复后必须复检**：修复完成后 → `/check --quick` 验证 → 受影响维度分数回升 → 否则继续修复。禁止修复后直接标记完成不跑复检。（护栏 A+C 自动校验数字一致性）

## 正例

> `/lint --full --verbose` → 18 项逐项检查 → 输出完整体检报告 → 标注每项通过/未通过 → 未通过项附带修复建议

## 反例

> 只跑 `/lint` 不看深度检查 → 遗漏隐性矛盾（第 7 项）和内容过时（第 12 项）
> Lint 发现问题后不修复、不复检 → 问题堆积

## 例外

### 例外1：页面增长回退
- 触发条件：页面数增长 >50%
- 例外行为：回退固定阈值 3 次，重建动态基线
- 标志动作：回复标注 `[基线重建]`

## 日常检查（9 项）

| # | 检查项 | 联动动作 | 修复方式 |
|:---:|------|------|------|
| 5 | 反模式触碰 | → 触发 `/audit`（含反模式审查） | 高置信自动标记+一行告知 |
| 6 | AGENT.md 行数 | >180 → 触发 `/compact` 行数精简 | 人类确认后执行 |
| 8 | YAML 格式校验 | 错误自动修复并标注 | 自动修复 |
| 9 | 链接密度 | <3 → 触发 `/dedup` 去重 → 碎片化候选 → `/compact` 合并；>15 → 仅告警 | 仅告警 |
| 10 | scene+domain 一致性 | 不匹配→告警 | 自动修复/告警确认 |
| 11 | draft堆积>30天 | → 触发 `/refresh`，高置信自动输出清单 | 提醒人类审查 |
| 14 | 疑似重复页面 | → 触发 `/dedup` 去重 → 确认后触发 `/compact` 合并 | 人类选择处理方式 |
| 15 | `updated` 字段缺失 | 扫描→自动补填 | 自动补填（无法推断→标 `[缺updated]`） |
| 16 | `review_date` 过期 | → 触发 `/refresh`，高置信自动输出《过期清单》 | 提醒人类确认或更新 |

## 深度检查（9 项）

| # | 检查项 | 联动动作 | 修复方式 |
|:---:|------|------|------|
| 1 | 页面矛盾 | → 触发 `/conflict` 矛盾裁决 | 人类裁决后修复 |
| 2 | superseded/deprecated 清理 | → 自动标记 `[待搬家]` → 触发 `/audit` | 高置信自动标记+一行告知 |
| 3 | 孤立页面 | → 触发 `/dedup` 去重扫描 | 建议交叉引用 |
| 4 | 缺失交叉引用 | → 输出《缺链清单》 | 建议→确认→补写 |
| 7 | 隐性矛盾 | → 触发 `/conflict` 矛盾裁决 | 人类裁决后修复 |
| 12 | updated>90天的active页面 | → 触发 `/refresh`，高置信自动输出《刷新建议》 | 人类确认后更新 |
| 13 | Git健康(commit>7天/untracked>10/仓库>500M) | → 触发 `/verify` 交叉校验 | 提醒人类处理 |
| 17 | `superseded_by`/`replaces` 断链 | → 输出《断链报告》 | 人类修复或清理无效引用 |
| 18 | 版本状态不一致 | `replaces` 指向的页面仍为 `status: active`（应为 superseded） | 提醒人类修改旧页面状态 |
