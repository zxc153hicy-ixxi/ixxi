# 代码审查规范

## 约束

1. 审查触发：用户请求审查代码 / PR diff / 脚本变更后 / Ingest 流程中涉及转换脚本时
2. 审查维度：正确性（逻辑/边界）、跨平台兼容（Windows/Unix差异）、健壮性（错误处理/资源清理）、可维护性（命名/注释/重复代码）
3. 发现 bug 必须给出：根因 + 影响范围 + 修复方案 + 验证方式
4. 输出格式：按严重度分级（CRITICAL/MAJOR/MINOR），CRITICAL 立即修复，MAJOR 本次会话内修复，MINOR 记录留待后续

## 正例

> 审查 batch-ocr.py → 发现 `Path.rename()` 在 Windows 上不覆盖已存在目标 → 定位到 Unix/Windows 行为差异 → 修复为 `Path.replace()`（跨平台原子替换） → 验证修复后重新跑 OCR 成功

> 审查 batch-convert.py 去重逻辑 → 发现 0KB 文件被当作"已处理"跳过 → 修改为检查 `st_size > 0` → 0KB 残留文件自动重新转换

## 反例

> 只跑了语法检查就说"没问题" → 跳过了逻辑审查 → 线上炸了 → 回来看发现是平台差异 bug

> 发现了问题但不追溯根因 → 只修了表面 → 同类问题在另一个脚本又出现

## 跨平台检查清单

| 陷阱 | Unix | Windows | 审查要点 |
|------|------|------|------|
| 文件覆盖 | `rename()` 静默替换 | `rename()` 抛 `FileExistsError` | 用 `replace()` 替代 `rename()` |
| 路径分隔符 | `/` | `\` | 全部用 `/`，`Path()` 自动转换 |
| 换行符 | LF | CRLF | 写文件时指定 `newline='\n'` |
| 编码 | UTF-8 默认 | GBK 默认 | 显式 `encoding='utf-8'` |
| 大小写 | 区分 | 不区分 | 文件名比较用 `casefold()` |
| 文件锁 | 允许删打开文件 | 禁止删打开文件 | `try/finally` + `with` 语句 |

## 原子写入检查

脚本写文件的正确模式：写临时文件 → 原子替换

```
正确：tmp = path.with_suffix('.tmp'); write(tmp); tmp.replace(path)
错误：直接 write(path)  — 中断留半截文件
错误：tmp.rename(path)  — Windows 上目标已存在时报错
```

## 例外

### 例外1：仅语法审查
- 触发条件：用户明确说"只看语法"或"快扫一遍"
- 例外行为：仅跑 `py_compile` + 明显语法错误，不审查逻辑
- 标志动作：输出标注 `[仅语法审查]`

### 例外2：第三方库代码
- 触发条件：文件标注 `# vendored` 或来自外部依赖
- 例外行为：跳过审查，仅记录版本号
