# 复杂度分层

> 8 份审查报告共识："方向应该从'加机制'转向'减复杂度'。"

知识库功能不是越多越好。按使用频率分为三级，新用户从 L1 开始，逐步解锁。

## L1 · 日常必用（每次会话都可能用到）

| 功能 | 说明 |
|---|---|
| G 层约束 | 20 条铁律自动加载（G1-G19 含 G16.5），无需手动操作 |
| `/lint` | 9 项日常检查，30 秒跑完 |
| `/ingest` | raw → knowledge 入库提炼 |
| `/health` | 健康度评分+页面数+commit+分布快照 |
| 索引页 | 全局 MOC + 目录索引，两级导航 |
| 文件命名规范 | 中文优先，看名知义 |
| G15 泛化提醒 | 自动匹配 patterns/anti-patterns，高置信度不阻塞 |

## L2 · 按需使用（出问题时才触发）

| 功能 | 触发场景 |
|---|---|
| `/lint --full` | 感觉知识库有点乱时 |
| `/dedup` → `/compact` | Lint 发现重复/碎片时 |
| `/audit` | 怀疑有遗漏+反模式积累时 |
| `/refresh` | 怀疑内容过时时 |
| `/verify` | AGENT.md 改过后 |
| superseded 搬家 | 合并操作后 |
| G 层修改流程 | 改核心规则时 |

## L3 · 低频高级（一个月未必用一次）

| 功能 | 触发场景 |
|---|---|
| `/compact` | AGENT.md >180 行（极少触发） |
| `/conflict` | 规则之间发现矛盾 |
| `/analyze` | 重大决策前的五维评分 |
| `/promote` | R→G 升层候选检查 |
| `/export-template` | 分享知识库骨架给别人 |
| Agent 审查团 | 深度架构审查（已跑过一轮） |

## 两个易混淆概念

| 概念 | 含义 | 用在 |
|---|---|---|
| **confidence** | LLM 对操作正确性的信心（高/中/低） | Ingest Step 3、G12 自动执行判定、G15 泛化提醒 |
| **status** | 页面生命周期状态（active/draft/superseded/deprecated/archived） | 所有 wiki 页面 YAML |

> 没有 trust 这个概念。审查报告提到的 "trust" 实际上是 status 字段的误读——status 管理的是页面生命周期，不是信任级别。
>
> （注：此处的 trust 指内容/页面层面的分级概念。技能系统（core/skills/）使用独立的 `trust: core/verified/draft` 三级元数据管理 curator 加载行为，详见 [[故障处置流程]]。）

## 两个 skills 目录

| 目录 | 用途 | 状态 |
|---|---|---|
| `.claude/skills/` | 旧版 skill 目录，含 `_archived`/`_external`（外部技能）/`kb`（junction） | **废弃** |
| `core/skills/` | 新版 skill 目录，curator 统一管理 16 个操作 skill | **当前** |

AGENT.md 路由指向 `core/skills/`，旧目录仅保留作兼容引用。不要混用。
