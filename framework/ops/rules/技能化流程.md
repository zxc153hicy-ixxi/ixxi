# 技能化流程

> 知识库自我优化引擎：检测重复操作 → 提议封装 → 生成 skill → 生命周期跟踪 → 归档

## 约束

1. 规则文件 = 单一事实源，skill = 精简执行入口（~200 词），内部引用规则文件完整步骤
2. skill 加载失败 → 自动降级读原规则文件
3. curator 自身也是一个 skill（自管理）
4. 所有生成操作需用户确认（G12），计数器维护为自动操作
5. **计数器自动更新**：每次执行可封装操作后，LLM 必须自动更新 `raw/sessions/skill-usage.json`：`count++` + 更新 `last_seen`（首次则设置 `first_seen`）。此为非破坏性自动操作（G12），无需用户确认
6. **接受状态跟踪**：skill 被加载时，若 `skill_accepted` 为 null（首次），用户接受后写入 `true`，拒绝写入 `false`；已为 `true` 则下次同操作直接走高置信度静默加载

## 五阶段生命周期

| 阶段 | 动作 | 触发 |
|------|------|------|
| 检测 | `/lint` 统计操作调用频次，写入计数器 | 每次执行可封装操作时 |
| 提议 | `/lint` 输出《技能化候选清单》 | 达到自适应阈值 |
| 生成 | LLM 读规则文件 → 生成 SKILL.md → 写入 `.claude/skills/kb/` + 更新 AGENT.md T层路由 | 用户确认 |
| 跟踪 | 记录调用次数/补丁/最后使用 | skill 已激活 |
| 归档 | 移至 `.claude/skills/_archived/`，路由回退规则文件 | 超期未使用 或 规则文件已更新 |

## 自适应阈值

| 阶段 | 判断条件 | 检测窗口 | 触发频次 | 归档时间 |
|------|------|------|------|------|
| 刚起步 | skill 总数 < 4 或 wiki 页面 < 80 | 7 天 | ≥2 次 | >90 天 |
| 在用了 | skill 4-8 或 wiki 80-150 | 30 天 | ≥3 次 | >90 天 |
| 用熟了 | skill > 8 且 wiki > 150 | 90 天 | ≥5 次 | >90 天 |

- 自动过渡：每次 `/lint` 检查 `skill` 总数和 `wiki` 页面数 → 自动判断阶段 → 跨越阈值时更新 `_meta.stage` + 提示用户
- 回退保护：skill 大量归档导致数量骤降 → `/lint` 检测到后自动回落上一阶段
- 归档时间统一 90 天，避免成熟期 skill 过早退役

### 阶段自动检测（`/lint` 执行时）

```
读取 skill-usage.json _meta.stage
读取 .claude/skills/kb/ 目录数（不含 _archived）
读取 find wiki -name "*.md" | wc -l
→ 对照阈值表判断当前阶段
→ 若与 _meta.stage 不同 → 更新 + 提示用户「阶段已切换」
```

## 置信度加载

操作触发时，按置信度分级决定 skill 加载方式：

| 置信度 | 条件 | 行为 | 通知文案要求 |
|------|------|------|------|
| 高 | 精确匹配（用户用 `/命令`）且 skill 已被接受过 | 静默加载，一行提示 | 大白话，告知这个 skill 是干什么的 |
| 中 | 关键词匹配（用户说了操作名但没用 `/`）或 skill 首次使用 | 提示确认，用户同意后加载 | 大白话，告诉用户有这个工具可用，问是否要试试 |
| 低 | 模糊匹配或多个 skill 都可能适用 | 列出候选清单，等用户选 | 大白话，逐一说明选项能干什么，让用户挑 |

**多推荐**：命中一个 skill 时，附带 1-2 个关联 skill：

```
📌 已加载入库帮手：把聊天记录自动整理成 wiki 页面
   顺便提一句：整理完之后一般还要跑一下体检看看有没有新问题，再查一下有没有漏掉的文件
```

**关联表**（用于自动推荐）：

| 主 skill | 关联推荐 |
|------|------|
| ingest | lint（入库后体检）· audit（查漏） |
| lint | audit（查漏）· health（打分） |
| audit | lint（体检）· ingest（补入库） |
| session-close | ingest（入库）· verify（对账） |
| conflict | promote（升层）· compact（精简） |
| compact | promote（升层）· lint（体检） |

## 计数器

文件：`raw/sessions/skill-usage.json`

```json
{
  "操作名": {"count": N, "first_seen": "YYYY-MM-DD", "last_seen": "YYYY-MM-DD"}
}
```

- 每次执行可封装操作时 `count++` + 更新 `last_seen`
- `/lint` 时读取 + 判断是否达到阈值
- skill 封装成功后在对应条目追加 `skill_active: true`

## 操作分类：机械 vs 判断

| 类型 | 用什么 | 原因 | 示例 |
|------|------|------|------|
| 纯机械（计数/比对/格式检查） | **脚本** | 100% 准确，零 token，不依赖 LLM 理解 | stats、verify |
| 需要判断（分析/裁决/识别/交互） | **skill** | LLM 才能做 | ingest、conflict、audit |
| 混合（机械步骤 + 判断步骤） | **skill 调用脚本** | skill 负责判断，机械部分调脚本 | lint（lint-data.sh 查格式 + skill 做综合评分） |

**规则**：一个操作能写成脚本（确定输入→确定输出→无歧义）就不配 skill。skill 只用于必须 LLM 判断的操作。

## 可封装操作清单

| 操作 | 类型 | 复杂度 |
|------|------|------|
| ingest | skill | 高（10步+硬闸门） |
| lint | skill + 脚本 | 高（18项检查，5项脚本+13项判断） |
| audit | skill | 高（全量扫描+分级处理） |
| compact | skill | 中（四维评分） |
| conflict | skill | 中（裁决流程） |
| session-close | skill | 中（三件套） |
| dedup | skill | 低（相似度判断） |
| health | skill | 低（评分+建议） |
| promote | skill | 低（升层判断） |
| refresh | skill | 低（过时判断） |
| ~~stats~~ | 脚本 | `stats.sh` 已覆盖 |
| ~~verify~~ | 脚本（待建） | `AGENT.md↔log.md` 比对可机械化 |

## SKILL.md 模板

```markdown
---
name: kb-<操作名>
description: Use when executing /<操作名> or when the user says "<中文名>" "<关键词>". <一句话描述>.
---

# kb-<操作名>

## Overview
<一句话核心原则>

## Quick Reference
<速查表，2-4 列>

## 硬闸门
<不可跳过的确认/校验点>

## 降级
SKILL 加载失败时，直接读取：`ops/rules/<规则文件名>.md`
```

## 同步计数器

- 每次结构性改动 commit 后，若未同步设计方案，`skill-usage.json` `_meta.sync_pending` +1
- ≥3 次 → curator 拦停提醒「设计方案已有 N 次改动未同步，是否现在同步？」
- 同步完成后 → `sync_pending` 重置为 0
