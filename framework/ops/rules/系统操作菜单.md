# 系统操作菜单

> 触发词：`系统操作` `维护` `/help` `菜单` `做什么` `能干什么`

## 意图→指令映射

> LLM 规则：检测到以下意图表述时，**主动询问「要不要做 X？」**，不直接执行。用户确认后才动手。

| 你说什么（泛化） | 动作 | 指令 | 做什么 |
|------|:--:|------|------|
| "检查一下" "有什么问题" "健康吗" "体检" "跑一遍" | **体检** | `/check` | 全维度检查——断链、过时、冲突、版本号 |
| "太多了" "精简" "瘦身" "行数超了" "合并一下" | **瘦身** | `/compact` | 行数超 180→精简；文件太碎→合并 |
| "找一下" "搜" "有没有" "在哪" | **搜索** | `/search` | 全文或结构化检索 |
| "建一个" "改名" "删掉" "重命名" | **增删改** | `kb-do.sh` | 原子操作，自动同步索引 |
| "整理" "收录" "入库" "提炼" "这批资料" | **入库** | `/ingest` | raw/ → knowledge/，10步流水线 |
| "冲突" "矛盾" "打架" "不一致" | **裁决** | `/conflict` | 规则冲突分析+判定 |
| "评估" "可行性" "打分" "值不值得" "分析一下" | **评估** | `/analyze` | 五维加权评分 |
| "打标签" "富化" "补标签" "补元数据" "补充摘要" | **富化** | `/enrich` | 分析文章内容→补全 tags/summary/pt_phase |
| "导出" "打包" "备份" "迁移" | **导出** | `/export-template` | 知识库骨架打包 |

### 意图泛化规则

1. **不直接执行**：识别到意图后，先问「要不要做 X？」等确认
2. **不误触发**：日常闲聊不匹配，仅实质性运维意图才提示
3. **组合提醒**：检测到连续操作场景时，按联动链提醒下一步（如入库→建议复检）

### 体检四档

| 档次 | 指令 | 覆盖 | 耗时 | 什么时候用 |
|:--:|------|------|:--:|------|
| ① 快速 | `/check --quick` | 仅变更影响维度 | 秒级 | 刚改完文件/规则，确认没搞坏 |
| ② 标准 | `/check` | 自动化全量 55 项 | 分钟级 | 日常巡检，每周跑一次 |
| ③ 深度 | `/check --deep` | 自动化全量 + LLM 逐项判断 | 较长 | 月底大检，含 R→G 升层候选 |
| ④ 全量 | `/check --full` | 深度 + 人工抽查 | 最长 | 大版本发布前/季度全检 |

> 除 ① 外，体检发现问题后自动提醒联动操作（如碎片化→建议瘦身、过时→建议刷新）。

### 已合并到 /check 的旧指令

> `/health` `/lint` `/dedup` `/refresh` `/promote` `/audit` 现在都是 `/check` 的一部分，不用单独记了。

## 约束

1. 菜单只做路由映射——LLM 检测到运维意图后，展示对应操作选项，**不直接执行**
2. 意图泛化不误触发——日常闲聊不匹配，仅实质性运维意图才提示
3. 组合提醒——检测到连续操作场景时，按联动链提醒下一步
4. 操作定义统一在本菜单，具体执行逻辑在各规则文件

## 正例

> 用户："检查一下知识库" → LLM：展示四档体检选项（快速/标准/深度/全量），等用户选择 → 用户选"标准" → LLM 执行 `/check`

> 用户："这批资料整理入库" → LLM："要不要做入库（/ingest）？会走 10 步流水线，把 raw/ 资料提炼到 knowledge/。" → 用户确认 → 执行

## 反例

> 用户："检查一下" → LLM 直接跑 `/check --full`（违反约束：没问用户要哪一档，没等确认）

> 用户问"今天天气怎么样" → LLM 匹配到"检查"关键词，问"要不要做体检？"（违反约束：日常闲聊误触发）

## 例外

- 用户明确说「直接跑 /check --quick 不问」→ 跳过确认，立即执行
- 用户在同一会话中已确认过同类操作（如刚确认过 `/ingest`）→ 后续同类型操作可降级为一行告知，不重复确认
- G 层修改触发 `/check --quick`（联动链自动触发）→ 不询问，执行后告知结果

| 你做了 | → 接着做 | 原因 |
|---|---|---|
| `/check --deep` | → `/compact` | 发现问题就瘦身 |
| `/ingest` | → `/check --quick` | 入库完了复检一遍 |
| G 层修改 | → `/check --quick` → `/export-template` | 改核心 → 验变更 → 导出 |
| 文件重命名 | → `/check --quick` | 改名可能断链 |
| 知识更新 | → 标旧→搬 archive → `/check --quick` | 新旧交替流水线 |
