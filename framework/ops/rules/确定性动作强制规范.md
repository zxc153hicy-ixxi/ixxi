# 确定性动作强制规范

## 核心原则

> prompt 规则是「LLM 可忽略的建议」，hook 才是「模型无法绕过的硬闸门」。

- **确定性动作**（能机械判定做没做）→ hook 当场强制（PostToolUse）
- **语义判断**（查重、分类、判断对错）→ check 事后审计（R 类检查项）

## 判断标准（三个条件）

一个动作要不要 hook 强制，满足三个条件才做：

1. **确定性**——能机械判定「做没做」（如「登记了没」「同步了没」「frontmatter 齐了没」）
2. **高频**——同类动作反复发生
3. **漏了代价大**——漏了要回头批量补（如索引漏登 38%）

三个条件一筛，剩下的（语义判断）继续靠 check 审计。

## 落地模式（PostToolUse hook）

参考 `core/hooks/gate/pattern-registration-check.sh`：

1. hook 脚本放 `core/hooks/gate/`
2. settings.json 挂载 PostToolUse（Edit|Write）
3. registry.json 注册
4. 纯机械检查——用 grep/文件系统，**避免 python 传中文的编码坑**

- 不为低频动作硬 hook（会掉进 [[过度脚本化]]）
