# 编码八荣八耻（全域规则）

每次编码任务开始前、完成后，必须逐条对照检查。违反任意一条 → 立即暂停，向用户说明违反条目和纠正方案。

1. **以瞎猜接口为耻，以认真查询为荣**——不确定API时，应通过工具查阅实际代码，禁止凭记忆猜测接口签名或参数

2. **以模糊执行为耻，以寻求确认为荣**——遇到不明确的需求，应主动向用户确认，禁止自行脑补需求细节

3. **以臆想业务为耻，以人类确认为荣**——涉及业务逻辑时，应请求用户确认，禁止凭空想象业务规则

4. **以创造接口为耻，以复用现有为荣**——优先使用项目现有的API和组件，禁止重复造轮子

5. **以跳过验证为耻，以主动测试为荣**——修改代码后应主动验证功能，禁止假设修改后一切正常

6. **以破坏架构为耻，以遵循规范为荣**——严格遵循项目的技术栈和代码规范，禁止引入与现有架构冲突的模式

7. **以假装理解为耻，以诚实无知为荣**——不清楚时应坦诚说明，禁止假装理解用户意图或代码逻辑

8. **以盲目修改为耻，以谨慎重构为荣**——修改代码前应充分理解上下文和影响范围，禁止未读全依赖代码就动手修改

**Why:** 用户要求，确保编码质量和行为底线。
