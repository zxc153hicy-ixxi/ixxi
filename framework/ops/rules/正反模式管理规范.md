# 正反模式管理规范

> 正模式 = 验证有效的做法；反模式 = 踩过的坑。本规范管它们的完整生命周期：**命名 → 生成 → 合并 → 应用**。

## 核心目标

1. **写了就能用到**——「生效」绑定到「写」上，不是写和生效分两步
2. **无重复、无无用**——数量不设硬指标，但每条都精、每条都有对应场景
3. **真实生效**——「完成」的标准是「真实生效」（违规真被拦住），不是「做完了」（文档写完了）

## 环节一：命名（生成的前置）

生成一条正反模式，第一步先起好名，再写内容。

命名要满足两点，让「读名字就能判断本质」：

1. **体现核心主张**——名字能看出「这条到底在防什么 / 主张什么」
2. **体现区分维度**——两条主张相近但场景/阶段/对象不同，名字要能区分

反例：「设计先行」和「设计先行再实施」——名字几乎一样，但一个是「功能开发」、一个是「复杂改动」，名字没区分维度，导致要读正文才能判断是否重复。

**拿不准强制问**：名字相同但语义可能不同时，判断权在用户，LLM 不猜。

## 环节二：生成

- **触发**：同类问题/修正 ≥2 次（G15 主动沉积）
- **硬门槛**：根因相同才算同类（不是笼统的「类似」）
- **生成前强制查重**：已有相同/类似的 → 走合并，不新增
- **一次性事件不沉淀**：某次具体 bug 的偶然原因，不写成反模式

## 环节三：合并去重

- **触发**：定期全量扫描兜底 + 生成时前置查重
- **判断标准**：
  - **本质相同** = summary 表达同一核心主张（注意语义——名字相同语义可能不同，拿不准强制问）
  - **特例关系** = 一条是另一条的具体做法
- **方向**：通用吸收特例（特例写进通用条正文作为子场景）
- **目标**：无重复、无无用

首次实践（2026-08-13）：7 组合并，正反模式 85→77（正 45→42、反 40→35）。合并结果：设计先行≈设计先行再实施、双AI≈交叉验证、G层跳过确认≈跳过G层防误操作、推荐工具不验证≈环境能力不实测、修复一个制造另一个+agent破坏排版+脚本搬运→「不安全操作无保护」（改名体现核心主张）、机制化非一次性⊃修复即建护栏、同步遗漏⊃写文件不更新索引。

## 环节四：应用

写的时候强制三选一「生效方式」：

| 生效方式 | 条件 | 写了之后 |
|---|---|---|
| 脚本护栏 | 能写 check 脚本检测「又犯了」| 写的同时建脚本（默认自动）|
| 流程内嵌 | 不能脚本化，但能写进流程强制步骤 | 写的同时改流程文件 |
| LLM 触发 | 只能语义判断 | 标注「仅 LLM 触发」|

- 可脚本化的：**默认自动建脚本**，菜单开关可切「建议写」（先建议、用户确认再建）
- 只能语义的：靠 G15 场景匹配 + **触发统计**（让「写了没用」显形；需改 G15 后落地，见下方待办）
