# 版本管理规范

## 约束

1. 版本号格式：`V主版本.次版本.修订号`
2. 重大更新（新增/删除核心规则、修改架构骨架）→ 次版本号 +1
3. 中更新（修改已有内容、新增 Lint 项、调整阈值）→ 修订号 +1
4. 微更新（修正错别字、调整格式）→ 不升级，仅更新日期
5. G 层修改前必须 `git tag vX.X-pre-xxx` 备份当前版本
6. 每次版本变更同步更新 AGENT.md 标题行版本号

## 正例

> 新增 G12 → 次版本号 +1（V2.16→V2.17）→ git tag v2.16-pre-g2 → 修改 → 更新标题版本号 → log 记录

## 反例

> 新增一条核心规则但不升级版本号 → 版本号与内容不匹配
> G 层修改前不打 tag → 出问题无法回滚

## 例外

### 例外1：紧急修复
- 触发条件：修复拼写错误、格式损坏等不影响语义的变更
- 例外行为：可跳过 tag 备份，直接修复
- 标志动作：log 标注 `[紧急修复]`

## 内容级版本管理

单个 wiki 页面的知识更新，不触发知识库整体版本号变更。使用以下机制管理：

### 替换旧知识

当你对某个主题的认知更新时：

1. 创建/修改新页面，YAML 中加：
   ```yaml
   replaces: "[[旧页面标题]]"
   ```
2. 修改旧页面：
   ```yaml
   status: superseded
   superseded_by: "[[新页面标题]]"
   ```
3. 下次 `/lint` 会检查：
   - `superseded_by` / `replaces` 链接是否有效（#17）
   - 旧页面状态是否已改为 `superseded`（#18）
   - superseded 页面是否该搬去 archive（#2）

### 标记需复核的内容

对于不确定是否仍然有效的知识，设 `review_date` 字段：

```yaml
review_date: 2026-10-08
```

`/lint` #16 扫描已过期的 `review_date` 并输出《过期复核清单》。

### 与知识库整体版本号的关系

- 知识库整体版本号（如 V4.0.0）跟踪 AGENT.md + 规则架构的变更
- 单页内容更新仅体现在该页的 `updated` 字段
- 不因单页更新而升级知识库版本号

## G 层修改流程（原 _G层修改警告模板）

G 层修改前必须输出以下模板，不可跳过。人类回复「确认修改」前禁止执行任何修改。

### 警告模板

```
## ⚠️ G 层修改警告

| 项目 | 内容 |
|------|------|
| **影响范围** | [G层条目编号+名称 + T层受影响标签] |
| **当前规则** | [现有约束文本] |
| **拟修改为** | [新约束文本] |
| **受影响标签** | [关联标签列表] |
| **回滚方式** | `git checkout [tag] -- AGENT.md` |
```

### 四项确认清单

| # | 确认项 |
|:---:|------|
| 1 | 规则表述是否准确？ |
| 2 | 关联标签是否合适？ |
| 3 | 行数影响是否在 180 行以内？ |
| 4 | R 层规则文件是否已就位？ |

### 执行流程

用户回复「确认修改」→ git tag 备份 → 执行修改 → log 记录 → 交叉校验

### 例外：回滚操作
用户说「回滚到 tag vX.X」→ 可跳过警告模板，直接 git checkout 回滚，标注 `[G层回滚]`

## 评分锚定参照（原 _评分锚定标准）

### 四维精简评分（行数管控，>180 行触发）

| 维度 | 权重 | 1分 | 2分 | 3分 | 4分 | 5分 |
|------|:---:|------|------|------|------|------|
| 近期触发频次 | 30% | ≥90天未触发 | 60-89天 | 30-59天 | 7-29天 | 最近5次每次触发 |
| 场景覆盖 | 25% | 仅单一场景 | 2场景，1为主 | 2场景均等 | 覆盖3个场景 | 覆盖全部场景 |
| 违规代价 | 25% | 仅影响单次格式 | 影响会话内多轮 | 项目级返工 | 知识库结构损坏 | 数据丢失/安全风险 |
| 反馈印证 | 20% | sources为空 | sources 1条 | sources 2-3条 | sources 4条 | sources ≥5条 |

### 五维可行性评分（矛盾裁决）

| 维度 | 权重 | 1分 | 3分 | 5分 | 特殊规则 |
|------|:---:|------|------|------|------|
| 历史频次 | 25% | 首次出现 | 1-2次印证 | ≥3次印证 | — |
| 场景匹配 | 25% | 单场景 | 2场景 | 跨全部场景 | — |
| 失败代价 | 25% | 影响单次格式 | 项目级返工 | 数据丢失/安全风险 | ≤2分→总分锁死2.5 |
| 可逆性 | 15% | 需修正≥10页面 | 3-9页面 | 改一行YAML | — |
| 体系一致 | 10% | 与≥3条冲突 | 与1-2条需调整 | 无冲突 | — |
