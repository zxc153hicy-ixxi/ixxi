# 可行性分析流程

## 约束

1. `/analyze` 触发时，对方案进行五维加权评分（必要性/技术难度/资源投入/风险/收益），各维 1-5 分
2. 总分 ≥3.5 建议推进，2.5-3.5 需优化后重评，<2.5 建议放弃
3. 分析结果输出为结构化报告：评分矩阵 + 关键风险 + 替代方案 + 建议

## 正例

- 对"新增 OCR 管线"进行分析：列出 5 维度得分 + 各维依据 + 替代方案（手动标注/调用云API）
- 两个方案并列对比，等权评分后推荐高分方案

## 反例

- 直接说"这个可以做"或"这个做不了"，无评分矩阵
- 只给结论不列风险，用户无法权衡

## 例外

- 用户明确说"不用打分，直接说结论"时，跳过评分矩阵，但仍需列出关键风险

## 步骤

1. 确认分析对象——明确要评估什么
2. 五维评分——逐维度打分 + 一句话依据
3. 风险识别——列出 ≥2 个关键风险 + 缓解措施
4. 替代方案——列出 ≥1 个替代方案 + 对比
5. 输出建议——一句话结论 + 行动项
