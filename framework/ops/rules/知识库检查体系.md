# 知识库检查体系

> **设计依据**：整合 Lint 18 项 + Audit 4 项 + Verify 交叉校验 + 检查报告模板，统一为 `/check` 单一入口。新增可移植性维度。

---

## 九维度总览

| # | 维度 | 检查项数 | 说明 |
|:---:|------|:---:|------|
| ① | 结构完整性 | 8 | 文件/目录/链接/索引是否存在、是否完整 |
| ② | 一致性 | 8 | 路径/数字/版本/引用是否自洽 |
| ③ | 规则完备性 | 6 | G层/T层/反模式/标签是否覆盖全面 |
| ④ | 可执行性 | 8 | 脚本/配置/流程是否可运行，含脚本碎片化检测 |
| ⑤ | 安全性 | 5 | 敏感信息/权限/确认流程是否到位 |
| ⑥ | 可维护性 | 5 | 单一事实源/变更追溯/文件自描述 |
| ⑦ | 用户体验 | 4 | 复杂度分层/新手引导/操作菜单 |
| ⑧ | 长期健康 | 7 | 健康度/时效/规模/自愈 |
| ⑨ | 可移植性 | 4 | 路径独立/跨平台/依赖清单/导出完整 |
| **合计** | | **55** | |

**评分**：每维度 0-10 分，等权平均 → 总分 /10。

| 评级 | 分数 |
|------|:---:|
| 优秀 | ≥9.0 |
| 良好 | 8.0-8.9 |
| 合格 | 7.0-7.9 |
| 需改进 | 6.0-6.9 |
| 不可用 | <6.0 |

## 三层执行模型

| 层 | 执行者 | 覆盖 | 说明 |
|------|------|------|------|
| **自动化检查** | 脚本 | 结构/一致性/可执行(脚本部分)/安全扫描/可移植(路径检测) | `run-all-checks.sh` 或逐个脚本调用 |
| **LLM 判断** | LLM | 规则完备性/可执行(流程部分)/可维护性/UX/长期健康(趋势) | LLM 逐项阅读后打分 |
| **人工抽查** | 人类 | UX 新手走查、安全敏感项确认 | 模拟新用户首次使用 |

---

## 五频率触发

| 频率 | 触发条件 | 执行范围 |
|------|------|------|
| **变更后** | G层修改 / 目录结构变更 / 脚本增删 / 规则文件增删 | 受影响的维度 |
| **周检查** | 每周一次（建议周末） | 自动化全量 + LLM 判断核心项 |
| **月检查** | 每月一次 | 全量（自动化 + LLM 判断） |
| **季度检查** | 每季度一次 | 全量 + 人工抽查 |
| **全量检查** | 手动触发 `/check --full` | 全部 55 项 |

## 执行步骤

> 每项标注：执行者、输入文件、具体命令/判断逻辑、通过标准、输出格式。

### ① 结构完整性

#### S1 · 核心文件存在 [A]
```bash
for f in AGENT.md index.md queue.md log.md activation.md GETTING-STARTED.md; do
  test -f "$REPO_ROOT/$f" && echo "✅ $f" || echo "❌ 缺失: $f"
done
```
**通过**：全部存在。缺 1 个扣 2 分。

#### S2 · 核心目录存在 [A]
```bash
for d in knowledge ops raw engine .inbox core; do
  test -d "$REPO_ROOT/$d" && echo "✅ $d" || echo "❌ 缺失: $d"
done
```
**通过**：全部存在。缺 1 个扣 2 分。

#### S3 · Wikilink 无断链 [A]
```bash
python engine/scripts/check-links.py --repo "$REPO_ROOT" --mode broken
```
脚本逻辑：遍历所有 `.md`，正则提取 `[[...]]`，去除 `|` 别名部分，解析为目标路径，检查文件是否存在。排除外部链接（`http://`）、锚点链接（`#`）。
**通过**：断链数 = 0。每 5 个断链扣 1 分，上限扣 5 分。

#### S4 · 脚本引用文件存在 [A]
```bash
python engine/scripts/check-script-refs.py --repo "$REPO_ROOT"
```
脚本逻辑：扫描 `engine/scripts/*.py` 和 `ops/scripts/**/*.sh`，提取字符串中的路径引用，检查目标是否存在。
**通过**：全部引用可解析。每 3 个无效引用扣 1 分。

#### S5 · `core/` 非空 [A]
```bash
find "$REPO_ROOT/core" -type f | head -1
```
**通过**：有输出。为空扣 10 分（结构性问题）。

#### S6 · `index.md` ↔ 实际文件一致 [A]
```bash
python engine/scripts/check-links.py --repo "$REPO_ROOT" --mode index
```
脚本逻辑：① 解析 `index.md` 中所有 `[[link]]` → 逐条验证目标 `.md` 存在；② 扫描 `knowledge/` + `ops/` 下所有 `.md` → 检查是否被 `index.md` 或子索引页收录。
**通过**：死链 = 0 且未收录 ≤ 5。每条死链扣 1 分。

#### S7 · 文件命名规范 [A]
```bash
python engine/scripts/check-naming.py --repo "$REPO_ROOT"
```
脚本逻辑：① 扫描通用名（`index.md` / `README.md` / `设定.md` / `大纲.md` / `提示词.md`）→ 标记；② 全库同名文件检测；③ 同目录前缀一致性检测。
**通过**：通用名 ≤ 3 且无同名冲突。超限扣分。

#### S8 · `.inbox/` 健康 [A]
```bash
python engine/scripts/check-inbox.py --repo "$REPO_ROOT" --mode health --max-age 7
```
脚本逻辑：① `.inbox/converted/` 中创建时间 >7 天的 `.md` → 列出；② `.inbox/` 下残留 `.tmp` 文件 → 列出；③ `.inbox/` 目录总大小。
**通过**：无过期文件且无残留 .tmp。有过期文件扣 3 分。

### ③ 规则完备性

> 全部为 LLM 判断。LLM 读取相关文件后逐项打分（0-10），附判断依据。

#### R1 · 规则零至七齐全 [L]
读取 `ops/rules/` 下所有规则文件，检查每个文件是否包含以下 8 个标准章节：
| 零 | 一 | 二 | 三 | 四 | 五 | 六 | 七 |
|------|------|------|------|------|------|------|------|
| frontmatter | 约束 | 正例 | 反例 | 例外 | 速查/步骤 | 字段/约定 | 关联 |

**评分**：缺一个章节扣 1 分。≥3 个文件缺章节额外扣 2 分。

#### R2 · G层约束覆盖核心场景 [L]
读取 AGENT.md G 层（G1-G17），逐条判断：是否有明确触发条件、是否与其他 G 层约束无冲突、是否为死规则（从未触发过）。
