# 核心操作流程

> 速查汇总。详细步骤见 [[Ingest完整流程]] 与 [[Lint检查流程]]。

## Ingest 10步流水线（0→9）

知识提炼全流程，0→9 严格顺序执行。详细定义见 [[Ingest完整流程]]。

| 步骤 | 名称 | 操作 | 失败处理 |
|:---:|------|------|------|
| 0 | 预检 | 扫描 personal/data/queue.md + personal/data/inbox/converted/ + personal/data/inbox/ + notes/，跳过 _processed | 失效标记 `[!]` 跳过 |
| 1 | 读取 | 逐条读 personal/data/inbox/ 与 personal/raw/，提取核心主张。来源为 personal/raw/→跳转 1.5 | — |
| 1.5 | 本地解析 | PDF/DOCX/TXT→拆分→写入 personal/data/sessions/→加入 Ingest 队列 | 移至 personal/data/inbox/_failed/ |
| 2 | 冲突扫描 | 按 scene+type 分桶比对。高置信度暂停；中置信度继续+标注；低置信度不告警 | 高置信度暂停等待裁决 |
| 3 | 写入 | 新建页按 confidence→status。high→active, medium→draft, low→draft+标记 | 重试一次；仍失败 log+跳过 |
| 3.5 | 对话确认 | 逐条展示 medium/low 内容。确认→active+回补引用；修改→重写；跳过/无回应→保留 draft。draft>60天→归档 | 确认/修改/跳过 三选一 |
| 4 | 交叉引用 | 仅 active 页面建立交叉引用（每页≥1→已有 wiki，+1→项目入口） | — |
| 5 | 校验 | YAML 格式 + scene 一致性 | 格式错误自动修复 |
| 6 | 更新索引 | index.md 追加 `- [[路径]] —— summary` | 冲突→临时文件 |
| 7 | 版本清理检查 | 跑 cleanup-versions.py --json，发现可清理旧版→提示；无→静默跳过 | 脚本异常→警告不阻断 |
| 8 | 提交 | queue[x]→log→git status 确认→git commit。检测 index.lock 残留→提示清理 | git 失败→人工介入 |
| 9 | 变更摘要 | `处理N条(其中converted M条, data/inbox K条) \| 新建X(其中draft A条) \| 更新Y(其中under-review B条) \| 冲突Z` | — |

**批量模式**：>30天未 Ingest→每批 ≤10 条按时间倒序处理，回复标注 `[批量模式: 第N批/共M批]`。

## 检查（/lint 已统一到 /check）

> 已统一到 `/check`（55 项检查体系），`/lint` `/health` `/audit` 等旧指令都是 `/check` 的一部分，详见 [[知识库检查体系]]。以下 Lint 明细保留作历史参考。

知识库自动化体检，分日常和深度。详细定义见 [[Lint检查流程]]。

### 日常检查（9项）

| # | 检查项 | 联动动作 | 修复方式 |
|:---:|------|------|------|
| 5 | 反模式触碰 + 循环检测 | 自动追加根因分析；同一警告连续 ≥3次→标记[人工处理]，不再自动修复 | 人类裁决后修复 |
| 6 | AGENT.md 行数 | >180 输出精简建议 | 人类确认后执行 |
| 8 | YAML 格式校验 | 错误自动修复并标注 | 自动修复 |
| 9 | 链接密度 | <3 孤岛候选，>15 过密 | 仅告警 |
| 10 | scene+domain 一致性 | 不匹配→告警 | 自动修复/告警确认 |
| 11 | draft 堆积 | >30天→告警，输出《待确认清单》 | 提醒人类审查 |
| 14 | 疑似重复页面 + 技能化候选 + 阶段检测 | 输出《重复内容报告》；读取 `personal/data/sessions/skill-usage.json` → 自动检测阶段切换（skill数+wiki页数 vs 阈值表）→ 达自适应阈值时追加《技能化候选清单》 | 阶段切换自动执行，技能化人类选择 |

### 深度检查（9项）

| # | 检查项 | 联动动作 | 修复方式 |
|:---:|------|------|------|
| 1 | 页面矛盾 | — | 人类裁决后修复 |
| 2 | deprecated 清理 | — | 仅告警 |
| 3 | 孤立页面 | — | 建议交叉引用 |
| 4 | 缺失交叉引用 | — | 建议→确认→补写 |
| 7 | 隐性矛盾 | — | 人类裁决后修复 |
| 12 | 内容过时（active 页面 updated>90天） | 与近期新知识比对→输出《刷新建议》 | 人类确认后更新 |
| 13 | Git 健康（commit>7天/未跟踪>10/仓库>500M） | 输出《Git 健康报告》 | 提醒人类处理 |

**输出模式**：
- `/lint` — 摘要模式（仅需行动项）
- `/lint --full` — 日常+深度 18 项
- `/lint --verbose` — 完整明细

**阈值策略**：冷启动前 5 次固定阈值，之后切换动态基线（近 5 次均值 ×1.5/×2.0）。页面增长 >50%→回退固定阈值 3 次重建基线。

## 系统健康度

```
健康度 = (自动化通过率 × 50) + ((1 - 反模式触碰率) × 50)
```
> 自动化通过率 = 55项检查体系中脚本检查的通过比例（见 `check-health.py`）

| 区间 | 状态 | 动作 |
|------|------|------|
| ≥70 | 健康 | 常规维护 |
| 50-70 | 预警 | 关注趋势，下次 /check 复查 |
| <50 | 异常 | 触发专项修复 |

**权重**：自动化通过率 : 反模式触碰率 = 50 : 50。8 次检查后 LLM 建议校准。

## 双引擎机制

知识库治理由两个引擎协同驱动：

| 引擎 | 职责 | 机制 |
|------|------|------|
| **Lint 引擎** | 守底线——发现问题 | 18 项自动化检查（9 日常 + 9 深度），冷启动→动态基线自适应 |
| **反馈闭环引擎** | 管进化——推动改进 | 人类反馈→正/反模式提炼→Lint 扫描触碰→根因分析→AGENT.md 演进 |

**核心闭环链路**：

```
人类评价 → 会话结束确认 → 写入 personal/data/feedback/
→ Ingest 提炼为 personal/system/patterns/ 或 personal/system/anti-patterns/
→ Lint 扫描触碰反模式 → 根因分析
→ G 层规则迭代 → 下次执行受新规则约束
→ 再次触发人类评价 ...
```

**权重校准**：系统健康度公式中两引擎 50:50 权重，运行 8 次 Lint 后由 LLM 结合反模式触碰率和 Lint 通过率趋势建议校准方向，人类最终确认。

## 反模式生命周期

反模式（anti-pattern）经历 5 种状态，按触发频率和时效自动迁移。**阈值与技能化系统共享同一套三阶段判断（skill 数 + wiki 页数），但方向相反**：存量少时保留更久（避免误删），存量多时清理更快。

### 三阶段状态

| 状态 | 含义 |
|------|------|
| **active** | 活跃监控中 |
| **suspended** | 临时挂起（人类裁决当前场景不适用） |
| **deprecated** | 已废弃（不再触发告警） |
| **强制修订** | 高频触发，必须修改对应规则 |
| **复活** | 从 deprecated 重新激活 |

### 自适应阈值（与技能化共用阶段判断）

| 阶段 | active→deprecated | 强制修订阈值 | 逻辑 |
|------|:---:|:---:|------|
| 刚起步 | >180 天 + ≥10 次未触发 | ≥10 次 | 数据少，宁可留着也别错删 |
| 用起来了 | >120 天 + ≥7 次未触发 | ≥20 次 | 数据积累中，适度清理 |
| 用熟了 | >90 天 + ≥5 次未触发 | ≥30 次 | 数据多，果断清理高频反模式 |

### 迁移规则

1. `active → deprecated`：自动触发，阈值见上表。标记 `deprecated: YYYY-MM-DD`，保留页面不删除，**同时主动提示用户是否移至 `personal/knowledge/archive/`**
2. `active → suspended`：人类手动操作。YAML 加 `suspended: YYYY-MM-DD` + `suspended-reason`
3. `active → 强制修订`：自动触发，阈值见上表。LLM 输出《强制修订建议》，人类确认后修改对应 G/R 层规则，修改完毕重置计数器
4. `deprecated → 复活`：人类手动操作。移除 deprecated 标记，status 恢复 active，触发计数器归零
5. `suspended → active`：人类手动操作。移除 suspended 标记

**存储位置**：`personal/system/anti-patterns/`，一个反模式一个 md 文件，YAML frontmatter 必含 `status` 和 `summary`。

## 统一生命周期

知识库所有时间约束共享同一套三阶段判断。阶段由 `personal/data/sessions/skill-usage.json` 的 `_meta.stage` 统一管理，`/lint` 时自动检测切换。

### 阶段判断

| 阶段 | 条件 | 含义 |
|------|------|------|
| 刚起步 | wiki 页面 < 80 或 skill 数 < 4 | 数据少，操作频繁，快速积累 |
| 在用了 | wiki 80-200 或 skill 4-10 | 数据积累中，适度放宽周期 |
| 用熟了 | wiki > 200 且 skill > 10 | 存量充足，严格筛选，稳定维护 |

### 各子系统阈值

| 子系统 | 刚起步 | 在用了 | 用熟了 | 说明 |
|------|:---:|:---:|:---:|------|
| 技能封装（窗口/频次） | 7天/≥2次 | 30天/≥3次 | 90天/≥5次 | 越早期越赶紧封 |
| 技能归档 | >90天 | >90天 | >90天 | 统一 |
| 反模式废弃（未触发天数/次数） | >180天/≥10次 | >120天/≥7次 | >90天/≥5次 | 越早期越舍不得删 |
| 反模式强制修订（触发次数） | ≥10次 | ≥20次 | ≥30次 | 越早期越容易触发修订 |
| draft 归档 | >30天 | >45天 | >60天 | 刚起步更新快，早归档 |
| Ingest 提醒 | 3天 | 7天 | 14天 | 刚起步要频繁入库 |
| 内容过时检测 | 60天 | 90天 | 120天 | 刚起步变化快，早检测 |
| Lint 频率 | 每次会话后手动 | 每周1次 | 每周1次+深度每2周1次 | — |
| 矛盾裁决超时 | 45天 | 45天 | 45天 | 固定，跟阶段无关 |
| 标签废弃 | 90天 | 90天 | 90天 | 固定 |
