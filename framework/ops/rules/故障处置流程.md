# 故障处置流程

> 汇总分散在 G 层/R 层的故障处理规则，一张表覆盖常见问题。

## 操作失败恢复

| 失败 | 恢复 | 来源 |
|------|------|------|
| Ingest 检测到高置信度矛盾 | 暂停 Ingest，输出《反馈冲突提示》，等人裁决 | G3 |
| Ingest 步骤 3 写入失败 | 重试一次，仍失败 log+跳过 | Ingest流程 |
| git commit 被 hook 拦 | 读 hook 输出 → 理解原因 → 报告用户 → 不重试 | 自动化 |
| 上下文 ≥80% | 输出简洁告警 → 等用户选「入库」或「继续」 | G14 |
| 上下文 ≥85% | 再次告警，建议立即入库 | G14 |
| medium 置信度矛盾 | 不暂停，继续 Ingest，变更摘要标注 | 矛盾消解流程 |
| raw/local/ 解析失败 | 移至 _failed/ | Ingest流程 |

## 循环检测（防死循环）

| 情况 | 阈值 | 动作 |
|------|:---:|------|
| 同一 Lint 警告连续出现 | ≥3 次 | 不再自动修复，标记 `[人工处理]`，等人裁决 |
| G14 连续告警但精简无效 | ≥2 次 | 停止提议精简，建议会话入库后重新开始 |
| git hook 连续拦截 | ≥3 次 | 停止重试，列出被拦原因等人修 |

## 信任级别

| 级别 | 标记 | 含义 | 影响 |
|------|------|------|------|
| 核心 | `trust: core` | 用户确认永不废弃 | 跳过自动归档、自动优化需确认 |
| 已验证 | `trust: verified` | 用户接受过 ≥3 次 | 静默加载 |
| 草案 | `trust: draft` | 新建未验证或准确率 <60% | 提示确认后加载 |

核心 skill（ingest/lint/audit/session-close）默认标记 `trust: core`。

> 此 trust 为技能系统元数据维度，与 [[复杂度分层]] 中讨论的内容分级概念不同。
