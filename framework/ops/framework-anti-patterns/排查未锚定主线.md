# 排查未锚定主线

## 发生了什么

git 保存时 commit 被 version-check hook 拦停，排查「设计文档在哪」时：
1. 先信 log.md 里记录的旧路径（Desktop 本地知识库搭建方案），认定设计文档在 Desktop，还提议「搬文件夹到 d:/」
2. 用户纠正「在 d 盘」后 find 到 docs/，但没锚定「当前会话主线是 ixxi 实施计划」，在「知识库设计方案-V4.3.1.md」与「ixxi 设计方案（designs/）」之间反复混淆
3. 用户连续纠正 3 次（「在 d 盘」→「designs 路径在这里」→「你在实施 ixxi 计划，怎么找到知识库设计方案了」），最后查 git 历史才定位到真位置 docs/

## 根因

排查时优先信了历史文档记录而非实测，且没在排查第一步锚定「当前任务主线是什么」。旧记录（log.md 的 Desktop 路径）早在 8月2日 已过时（文档已迁移到 docs/），但没先实测就直接采信；主线（ixxi）与排查对象（知识库设计方案）是两件事，没区分导致反复绕。

## 怎么修

1. 排查路径/位置类问题时，先实测（find/ls）再下结论，不先信文档里写的旧路径
2. 排查第一步先锚定「当前任务主线是什么」，判断排查对象与主线的关系，避免被无关概念带偏
3. 涉及「文档迁移过」的资源，先查 git 历史确认最新位置，而非信 log/索引里的过时记录
4. 用户纠正一次后，立刻停下重读原始诉求 + 当前主线，别在同一错误方向继续打转
