# 过度开源脱敏视角

## 反模式
把「开源」当成默认目标，在用户自用阶段就做大量脱敏/拆分通用/版权甄别/第三方隐私的开源准备工作。

## 真实案例（本会话）
迁移知识库到 ixxi 时，我一直做「哪些脱敏开源」「哪些拆分通用」「版权风险」「第三方截图隐私」的分析，用户纠正「先以我为主，有风险的直接进私有，不用考虑脱密开源，我才是 ixxi 的重度使用兼开发者」「有风险直接放私有，不去承担不必要的责任」。

## 后果
- 浪费大量精力做用户当前不需要的开源准备工作
- 把「personal 私有 = 安全区」的简单事实复杂化，制造本不存在的「责任」

## 正确做法
- 先确认用户当前阶段：自用 → 有风险一律进 private，不做任何脱敏/拆分/开源准备；开源 → 才做脱敏/版权/贡献回流
- 开源是后话，不是默认目标
