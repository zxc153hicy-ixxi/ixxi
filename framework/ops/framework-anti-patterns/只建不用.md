# 只建不用

> 反模式 = 踩过的坑。

## 发生了什么

搭了一整套框架机制（分层 G-T-R+skill、check 脚本、hook、正反模式、scope 二分），却一直处在「建/修」模式，没处在「用」模式——机制从没被真实任务点燃过。结果是：机制建了、挂着、看着在跑，实际没帮上忙，自己也「没体验到好处」。

实锤：4 个 check 脚本一直「扫空气还报通过」（假绿），说明连验证器自己都没被真实数据验证过；未落地清单里「dogfooding 3-5 真实场景」这条最大 gap 一直没补。

## 根因

把「机制建成」当成了「机制有价值」。但机制不自己产生价值，只在「用它做事」时体现。**建 ≠ 用 ≠ 帮到**。

## 怎么修

- 建成机制后，挑一件真实的事用它完整走一遍（dogfooding），诚实评估「帮到我没有」——帮了留、没帮删、坏了修。
- 停止继续建机制，先去体验现有的。体感比架构决策值钱，它才是当初建机制的「目的」。
- 可观测：机制有没有被真实触发、有没有省事，要有指标兜底（参考 [[机制建成未验证]]）。
