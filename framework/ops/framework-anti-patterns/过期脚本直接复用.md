# 过期脚本直接复用

> 反模式 = 踩过的坑。

## 发生了什么

用户说"调用 skill 进行修复"，直接找到 `engine/templates/kb-batch-fix-workflow.js`（V2.x 时代编写），差点直接跑。该脚本全部引用 `ops/rules/`、`wiki/projects/`（→ 已废弃）等 V2.x 路径，当前目录结构无 `wiki/`，33 项全部过时。直接跑 = 全部失败 + 浪费时间 + 可能误伤。

## 根因

- 脚本文件名和描述未标注适用版本
- 没有「执行前先验证路径存在性」的前置检查
- 先执行后思考（直接跑 workflow vs 先检查是否匹配当前状态）
- 用户指令"调用 skill"听起来像标准流程，实际 skill 已过时

## 怎么修的

先检查 `wiki/`（→ 已废弃）目录不存在 → 对比当前结构 → 确认全部 33 项已过时 → 创建设计文档 + 实施计划 → 重新执行。

## 怎么防

- 脚本/工作流头部标注适用版本号和前提条件（`# requires: V4.x, ops/ + knowledge/ structure`）
- 执行旧脚本前先跑前置检查（路径存在性、目录结构匹配）
- 设计先行：即使是"复用已有脚本"，也要先确认是否适用当前结构
