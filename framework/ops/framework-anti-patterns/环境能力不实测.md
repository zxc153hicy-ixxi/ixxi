# 环境能力不实测

## 发生了什么

对工具/环境能力做假设而不实测，两种场景：

1. **判断环境能力**：用户要求渗透测试时，直接回复"我没有网络出站能力"——基于对沙箱的先验假设，未实测。实测发现 curl（GET+自定义 Header）、Python socket（原始 TCP）都能正常出站。
2. **写工具推荐**：工具选型文档里写"PDF 文字型 → Pandoc"，实际 Pandoc 只能生成 PDF、不能读取 PDF，用户按文档执行报 `Unknown input format 'pdf'`。

## 根因

1. 训练数据中对环境/工具能力的泛化认知覆盖了实际能力
2. 应该"先问能不能"但变成"先告诉我不能"
3. 没有遵循 G16（知识优先）——应先查本地知识库是否有能力文档，没有则实测

## 怎么修

1. 涉及能力判断时，**先实测再结论**：用最小代价命令（curl / python -c）验证而非假设
2. 文档中每个工具×格式组合必须实测验证后才写入
3. 对用户说"不能"之前，必须已经在当前会话中跑过验证命令
4. 实测结果写入知识库，避免下次重复验证
