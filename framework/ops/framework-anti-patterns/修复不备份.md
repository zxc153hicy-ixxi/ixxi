# 修复不备份

## 发生了什么

知识库架构修复过程中：`rm -rf .claude/kb/skills/_archived/`（删除）→ `rm -rf .claude/skills/kb/`（删除11个skill副本）→ `mv _external/`（移动41个外部skill）→ `sync-agent-md.sh`（覆盖CLAUDE.md和HERMES.md）。全部未做任何事前备份。

## 根因

1. git 仓库提供了"事后回滚"的安全感，诱使跳过事前备份
2. G12（修改确认）已满足（用户说"执行吧"），但备份步骤不属于确认流程的一部分
3. `ops/scripts/_lib/git.sh` 的 `git_backup()` 函数存在但未被调用——工具建成但未强制使用
4. `.fix-backup/` 目录有上次修复的备份先例，但本次没有参考

## 怎么修

1. 破坏性批量操作前必须执行 `source framework/ops/scripts/_lib/git.sh && git_backup "<操作名>"`
2. `/enrich` 和 `check-ocr-quality.py --fix` 内置自动备份逻辑
3. 将备份步骤写入 G12 确认流程：确认→备份→执行
