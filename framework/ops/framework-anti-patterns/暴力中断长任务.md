# 暴力中断长任务

## 发生了什么

搭建视频转录工具时，LLM 最初的设计是让用户 `Ctrl+C` 中断 + `KeyboardInterrupt` 捕获保存断点。用户指出「冒然中断不会出问题吗」——暴露出 LLM 默认把信号中断当作"正常的停止方式"，没有考虑：

- 中断时机不可控：可能正好在文件写入中途 → 数据损坏
- Windows 上信号行为不可靠
- 用户操作门槛高（需要知道 `Ctrl+C`、找对终端窗口）

## 根因

LLM 训练数据中大量使用 `try/except KeyboardInterrupt` 模式，形成惯性思维——把应急手段当常规操作。

## 怎么修的

改为**信号文件机制**（→ [[信号文件优雅中断]] 正模式 #33）：
1. 用户对 LLM 说「暂停」→ LLM 创建标记文件
2. 脚本在安全检查点检测标记 → 保存 checkpoint → 优雅退出
3. 用户说「继续」→ `--resume` 从断点续传

## 识别特征

- LLM 提议"Ctrl+C 就行"、"kill 进程即可"作为长任务的停止方案
- 任务的上下文有价值（转录进度、已处理数据），中断后需要恢复
- 用户不是技术人员，不熟悉终端操作
