# 审查表面化

## 现象

收到"全面审查"任务 → 跑了 9 个自动化 check 脚本 → 统计几个数字 → 写报告声称"审查完成"。检查体系中 [L] 标记的 LLM 判断项（18/55 项）全部跳过。

## 后果

- 遗漏率 80%+（本次 18 项 [L] 只做了 3 项，漏 15 项）
- 只发现机械问题（断链、格式），漏掉语义问题（过时文档、矛盾声明、缺失引用）
- 用户拿到报告以为系统健康，实则隐患未暴露

## 与"检查偷懒"的区别

| | 检查偷懒 | 审查表面化 |
|------|------|------|
| 行为 | 用 `ls` 代替 `find` 递归 | 跑脚本代替逐文件细读 |
| 范围 | 目录排查 G9 | 全面审查 55 项 |
| 跳过的是 | 子目录文件 | LLM 判断项（语义理解） |

## 纠正

1. 审查前先确认：哪些是 [A]（脚本）、哪些是 [L]（LLM）、哪些是 [M]（人工）
2. [L] 项必须逐项打开文件、阅读、判断、记录，不可汇总统计替代
3. 审查报告标注每项 [L] 的实际覆盖情况（已覆盖/跳过/跳过原因）
4. 不确定时主动问"要不要补一轮深度审查"
