# 机制建成未验证

## 发生了什么

G17「Skill 自动调度」机制 2026-07-13 落地，文档完备、设计精良（20 条映射表 + 三步调度 + 四档优先级），但到 08-13 整整一个月 `scheduling_count=0`、一次都没触发，无人察觉。三重根因叠加：

1. **skill 二级嵌套不可见**：15 个内部 kb-* skill 放在 `.claude/skills/kb/<name>/SKILL.md`（二级），Claude Code 只扫描一级 `.claude/skills/<name>/SKILL.md`、不递归 → 全部不可见
2. **跨 agent 悬空引用**：G17 在 AGENT.md（Shared 层）要求「匹配 skill 映射表」，但映射表写在 curator SKILL.md（Claude-only 层）→ Hermes/Codex 读到 G17 却找不到表
3. **无 hook 兜底**：调度全凭 LLM 自觉，计数靠自觉记账，无任何 hook 强制或检测

## 根因

「文档写完、规则落地」被当成了「机制生效」。缺一个可观测的触发指标 + 首触发验证环节——机制上线后没人问一句「它真的被触发了吗？」。

## 怎么修

1. 建成任何「自动」机制后，设一个可观测指标（计数/日志/列表出现），并在下一会话验证它真的增长/出现
2. 涉及「发现/加载」的机制，先实测目标对象真的能被发现（如 skill 出现在可用列表），再宣称完成
3. 跨 agent 共享资源时，确认引用目标在「共享层」而非「某 agent 专属层」
4. 语义判断靠 LLM、机械兜底靠 hook——纯自觉的机制必然失守，至少补一条机械检测
