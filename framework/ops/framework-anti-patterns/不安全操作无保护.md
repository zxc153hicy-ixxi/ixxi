# 不安全操作无保护

## 触发场景

运行自动化操作（脚本修复 / agent 编辑 / 脚本搬运）时，操作逻辑未考虑数据安全护栏，导致文件内容损坏或丢失。

## 典型案例（三种）

1. **脚本修复破坏结构**：`check-ocr-quality.py --fix` 的 `fix_broken_paragraphs` 把连续非空行合并成段落，未识别 YAML frontmatter，`tags:` `status:` `type:` 三行被并成单行，250 个文件损坏
2. **agent 编辑破坏排版**：Workflow agent 编辑 frontmatter 时把多行段落合并成单行，内容不丢但严重破坏可读性，8 文件受损
3. **脚本搬运丢失数据**：auto-import.py 用 `shutil.move` 搬运用户原始文件，clean-inbox.py 随后删除，39 个 PDF 永久丢失（P0）

## 根因

- 操作函数缺上下文感知：不知道文件有 frontmatter 区要保护
- 操作后未验证：没跑关联检查脚本（如 check-frontmatter.py）验证完整性
- 批量操作无安全网：250 文件写坏才被发现
- 搬运用 move 而非 copy：源文件被移走后，后续删除造成不可逆丢失

## 预防

1. 批量操作前**必须在单文件 dry-run 验证**
2. 操作逻辑必须识别并跳过 frontmatter 区域（`---` 包裹的 YAML）
3. 操作后立即跑关联检查脚本验证完整性
4. 搬运用 copy 而非 move，删除前确认有备份
5. 用 YAML 库操作 frontmatter（`yaml.safe_load/dump`），禁止正则直接改
