# 排序字段位置错误

构造复合排序键时，把分类/格式标识码放在元组第一位，导致实际排序以分类码为主键而非业务值。本例中 `parse_version` 的 sort tuple 为 `(format_code, major, minor, tag)`，format_code 占首位→tagged v8 排到 numeric v11 前面。

## 根因

设计 sort tuple 时下意识把"类型标识"放在前面以区分不同格式，但 python tuple 排序按位置优先级，第一位权重最高。

## 教训

1. 排序键的第一位必须是最重要的业务字段（版本号的 major）
2. 格式/类型标识作为 tiebreaker 放在最后
3. 写完排序函数后立即用极端用例验证（不同格式的最大/最小值交叉对比）

## 关联

修复见 framework/engine/scripts/cleanup-versions.py parse_version 函数——tuple 从 `(format, major, minor, tag)` 改为 `(major, minor, patch, tag)`。
