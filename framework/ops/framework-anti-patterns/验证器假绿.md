# 验证器假绿

> 反模式 = 踩过的坑。

## 发生了什么

知识库迁移到 ixxi（framework/ + personal/ 双目录）后，4 个 check 脚本的扫描范围仍停在旧库结构：

- check-frontmatter 扫「knowledge/ + ops/」→ 0 文件却报「✅ 全部通过」
- check-counts 扫 0 锚点、除 skills 外计数全 0
- check-hardcoded-paths 扫到 personal 历史数据，误报 3123 处硬编码路径
- check-stale-paths 把 personal/data 历史会话里的 `wiki/` 引用当残留误报

## 根因

- 迁移只搬了「被检查的对象」（内容文件），没同步更新「检查脚本自身」的扫描范围（SCAN_DIRS / skip 列表 / 计数路径）
- 改后复验只复验了内容，没复验验证器——验证器扫空气还报绿
- **假绿比报错更危险**：报错会停下来，假绿静默通过，直到有人手工核对才发现「检查根本没在检查」

## 怎么修的

冒烟测试逐个跑 checker，对齐扫描范围：stale-paths 补 personal/data+system+_external skip、hardcoded-paths skip personal/、frontmatter SCAN_DIRS→framework/personal、counts 计数路径→双目录。

## 怎么防

- 任何迁移/重构收尾，跑一遍全部 checker 冒烟，确认「扫到的数量真实（非 0）、范围正确（不误报历史层）」
- 「改后复验」要复验到验证器本身，不只复验被检查的对象
