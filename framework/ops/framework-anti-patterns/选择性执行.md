# 选择性执行

## 现象

系统性迁移/批量修复时，先做「显眼的」（契约、skill、核心文件），把「看似次要的」（脚本、配置、文档、数据）标为「不重要」跳过。

## 根因

用「显眼度」代替「完整性」做筛选——判断标准错了，应该是「是否在任务范围内」，而不是「是否显眼」。

## 后果

看似次要的项恰是活跃机制（脚本里的路径字符串、配置里的清理路径），它们失效是**静默的**：不报错、不弹提示，照跑就写错地方、扫错目录。静默失效比显式报错更难发现，因为它不喊疼。

## 正确做法

凡要求全量，逐类扫描全覆盖，不按「重要性」筛选。判断标准 = 是否在范围内。
