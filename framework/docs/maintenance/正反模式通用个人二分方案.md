# 正反模式「通用/个人」二分方案

> 配套 [[分层收敛决策]]。解决正反模式「framework 死重 + personal 混源 + 双源无冲突规则」的问题。

## 一、问题（已核实）

| 事实 | 状态 |
|---|---|
| framework/ops/framework-patterns（3 条正模式） | 死重——无索引、无 hook、无 G15 接线 |
| personal/system/patterns（45）+ anti-patterns（43） | 混源——通用教训和个人教训搅在一起 |
| 双源冲突 | 无解决规则；framework-patterns 一旦挂机制即冲突 |

## 二、判据（隐私 + 绝大部分人有用，二合一）

**进 framework（通用）的充要条件：不涉隐私 AND 绝大部分人有用。**

- **隐私是硬闸门**：涉隐私一律 personal（隐私 > 通用性）。
- **换人是高门槛**：不涉隐私但只对少数人有用 → 也留 personal（通用不为少数人让步）。

| | 绝大部分人有用 | 少数人有用/没用 |
|---|---|---|
| **不涉隐私** | → framework | → personal |
| **涉隐私** | → personal | → personal |

## 三、目标态（选 A：正/反分离，与 personal 对齐）

```
framework/ops/
├── framework-patterns/        # 通用正模式（补索引 + 挂 hook，让死重活起来）
└── framework-anti-patterns/   # 通用反模式（新建）
personal/system/
├── patterns/                  # 个人正模式（现状保留）
└── anti-patterns/             # 个人反模式（现状保留）
单一机制：G15 匹配 + pattern-registration-check hook + 索引 + 遥测，读四个源
```

## 四、冲突规则

**个人覆盖通用（personal overrides framework）。** personal 是实例级特化，优先级高于 framework 通用默认。同主题冲突以 personal 为准。

## 五、实施步骤

| Phase | 动作 |
|---|---|
| 0 | 冻结 + 盘点 88 条（逐条判「涉隐私？绝大部分人有用？」） |
| 1 | 建 framework-anti-patterns |
| 2 | 通用教训 git mv 到 framework（保留历史） |
| 3 | 配机制（索引 + hook + G15 接线） |
| 4 | 冲突规则写进契约（G15 补「personal 覆盖 framework」+ CHANGELOG） |
| 5 | 验证（hook 跑通 + 索引完整 + check-links + parity） |

## 六、风险

- Phase 0 是判断活：88 条逐条判「涉隐私 + 绝大部分人有用」，「绝大部分人」带主观性，边界条目需人工拍板。
- git mv 后 personal 索引、G15 写入路径要同步改，check-links 兜底。
- 契约改 G15 走 pre-commit + CHANGELOG 确认条目。
