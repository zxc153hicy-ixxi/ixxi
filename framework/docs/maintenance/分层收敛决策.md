# 分层收敛决策（G-T-R+skill → 只收敛 T层）

> 本文档记录「四层冗余」的分析 + 决策 + 再评估触发条件。**以后若 R层/T层 出问题，先读这里。**

## 背景

ixxi 契约原为 G-T-R 三层（G 全局约束 / T 标签路由 / R 规则文件），后加 skill 层（16 个 kb-* 操作入口），长成四层。实际运行发现 T层、R层 几乎没被直接使用。

## 分析（2026-08-16 盘点）

| 层 | 规模 | 实际使用 | 结论 |
|---|---|---|---|
| G层 | 22 条 | 常驻，真正扛活 | 保留 |
| T层 | 16 标签→文件 | 路由被 G17 skill 路由取代，闲置 | 冗余 |
| R层 | 29 文件 | 18 个无 skill 引用，仅 11 个被 skill 引用 | 参考库，形式未对齐 Capability |
| skill | 16 个 | 实际入口（G17） | 保留 |

**三层路由重叠**：标签→skill→R层文件（G17 主路）／标签→R层文件（T层 旧路）／G层隐式加载（5 文件）。

## 决策（2026-08-16）

**只做 Phase 1（T层收敛），R层不动。**

- ✅ 已做：T层删「标签→规则文件」路由列，退为纯标签词表（G7 匹配用）；路由统一走技能化路由（标签→skill）；降级改 G层通用约束兜底。commit `fec1536`，tag `ixxi-converge-t-2026-08-16`。
- ❌ 不做：Phase 2（R层内联进 skill）、Phase 3（约定合并）。

## 为什么不做全量

- 这是**参考实现的整理，不是 ixxi 核心**（核心 = capability/parity/sync 那套）。
- 当前四层「能用」，无功能故障、无实际痛点。
- 风险集中在**静默型失败**（AGENT.md 契约行为悄悄跑偏、skill 引用静默断裂）——正是 [[验证器假绿]] 反模式的同类，比「崩了」更难察觉。

## 再评估触发条件（以后出问题，看这几条）

R层/T层 出现以下**实际痛点**时，再针对性收敛（不搞一次性大扫除）：

- 某流程总被跳过 → 对应 R层文件没被走到，考虑内联进 skill
- 某约定总被违背 → 约定散落难查，考虑合并/上浮 G层
- 某规则文件找不到 / 引用断链 → 该文件是孤儿，考虑删除或归档
- 新增操作时路由混乱 → T层词表与 skill 不匹配，考虑补 skill
