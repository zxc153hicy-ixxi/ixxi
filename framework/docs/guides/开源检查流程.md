# 开源检查流程

> **给谁**：开发者（维护者）。
> **什么时候跑**：首次开源前、每次 release 前、有外部贡献者加入前。
> **怎么跑**：`bash framework/engine/scripts/check-open-source.sh` 一键跑全部，或按下表逐项手动查。

## 检查清单

| # | 检查项 | 命令 | 达标标准 |
|---|------|------|------|
| 1 | 个人数据零残留 | `grep -rn '29909\|源质挽歌\|D:/KnowledgeBase\|C:/Users' framework/` | 零**真实**命中（检查标准示例 / 测试 fixture 除外） |
| 2 | 适配层产物不进 git | `git ls-files .claude .agents .codex` | 0 文件（适配层是 sync 生成的，应被 .gitignore 排除） |
| 3 | 敏感信息无真实泄露 | `python framework/engine/scripts/scan-sensitive.py --repo framework` | 无真实密钥/密码/身份证（test fixture 跳过） |
| 4 | git 工作区干净 | `git status --short` | 空 |
| 5 | 许可证就位 | `ls LICENSE` + 核对 CONTRIBUTING / cla.yml | LICENSE(MIT) + CLA + DCO 齐全 |
| 6 | README badge 真实链接 | `grep '<owner>' README.md` | 无 `<owner>/<repo>` 占位（换成真实仓库链接） |
| 7 | 版本一致 | `bash framework/core/hooks/gate/version-check.sh` | CHANGELOG ↔ git tag 一致 |

## 上传 GitHub 后补做（依赖真实仓库，本地做不了）

| # | 项 | 怎么做 |
|---|------|------|
| 8 | CI 真实运行 | 推送到 GitHub 后看 Actions，确认 ci.yml 四件套通过 |
| 9 | CLA 机器人 | 配置 cla-assistant + CLA_PAT |
| 10 | good first issue 标签 | 在 GitHub 打标签 + 挑几个适合新手的问题 |

## 检查项说明（为什么查这个）

- **#1 个人数据**：framework 是开源通用层，绝不能带你的账号、路径、项目名。命中处若是「检查标准示例」（如维护者手册里写「grep 29909 要零命中」），属预期；若是真实数据，必须脱敏。
- **#2 适配层产物**：`.claude/.agents/.codex` 是 sync 从 core 生成的副本，进了 git 会造成「改 core 但适配层没同步」的假象。发现 tracked 就 `git rm --cached`。
- **#3 敏感信息**：test fixture 里故意写的假密码（如 `hunter2`）不算泄露，但要确认 `framework/engine/tests` 已被 scan-sensitive 跳过，避免每次误报。
- **#6 badge**：README 里的 CI/Version badge 是 `<owner>/<repo>` 占位，开源后换成真实链接，否则徽章显示不出来。
