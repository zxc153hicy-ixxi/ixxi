# 用户编辑模型

ixxi 单目录分两层：`framework/`（开源通用层，机制）+ `personal/`（私有实例层，数据）。分层的核心收益是「升级不冲突」——用户误改 framework 文件会让升级时冲突、改动丢失。本文明确「哪些可改、哪些只读」。

> 口径与 `.gitignore` 排除一致：`personal/` 与框架适配层（`.claude/skills/kb-*`、`.claude/agents/`、`.agents/`、`.codex/`）不纳入版本库，升级不覆盖；settings 类配置属个人偏好，默认不提交（仓库根 `.claude/settings.json`、`.claude/settings.local.json` 已在 gitignore 排除），不提交即不随升级覆盖。

## 可改白名单

| 路径 | 可改 | 说明 |
|---|---|---|
| `personal/` | ✅ 全可改 | 私有实例数据 + 个人绑定 + 运行状态，gitignored，升级不覆盖 |
| `.claude/settings.json` | ✅ 可改 | 个人引擎配置（hooks / 权限等），个人偏好不提交，不提交则不随升级覆盖 |
| `.claude/settings.local.json` | ✅ 可改 | 本地私有配置，gitignored，升级不覆盖 |

即：**`personal/` 全可改；`framework/` 下仅 settings 类个人配置可改**。

## 只读清单

`framework/` 其余全部只读。升级（git pull 上游）时会覆盖这些文件，手改必丢。

| 路径 | 只读 | 为什么 |
|---|---|---|
| `framework/core/` | 🔒 | 能力源（skills/agents/hooks + registry），机制唯一事实源，升级覆盖 |
| `framework/ops/rules/` | 🔒 | 通用规则文件，升级覆盖 |
| `framework/ops/`（其余） | 🔒 | framework-patterns / hermes / scripts / templates，通用资产，升级覆盖 |
| `framework/engine/` | 🔒 | scripts / config / templates，通用引擎，升级覆盖 |
| `framework/docs/` | 🔒 | 通用文档（本文件亦由框架维护，非个人笔记位），升级覆盖 |
| `framework/knowledge/` | 🔒 | framework 通用知识，升级覆盖 |
| `framework/samples/` | 🔒 | 样例，升级覆盖 |
| `framework/AGENT.md` | 🔒 | 通用契约单一事实源（CLAUDE/HERMES/Codex 由它同步生成），升级覆盖 |
| `framework/index.md` | 🔒 | 全局导航，升级覆盖 |
| `framework/activation.md` | 🔒 | 操作入口注册表，升级覆盖 |
| `.claude/skills/kb-*` | 🔒 | 适配层生成产物：sync 脚本从 `core/skills/` 生成，升级重跑 sync 重建 |
| `.claude/agents/` | 🔒 | 适配层生成产物：sync 脚本从 `core/agents/` 生成 |
| `.agents/` | 🔒 | Hermes 适配层生成产物 |
| `.codex/` | 🔒 | Codex 适配层生成产物 |

## 修改只读文件的风险

- **升级丢失**：`framework/` 是版本化的通用层，升级 `git pull` 时只读文件会被上游版本覆盖，任何手改消失且无提示。
- **升级冲突**：手改后与上游同文件改动冲突，升级被迫停滞在解决冲突上，违背「升级不冲突」的分层初衷。
- **契约漂移**：直接改 `AGENT.md` / `core/` 而不同步改版本库，造成实例与开源层事实脱节；改生成产物（适配层）则被下次 sync 整体重建覆盖，等于白改。

## 正确姿势

| 想做什么 | 正确路径 | 理由 |
|---|---|---|
| 改通用机制（`core/` 能力源、`ops/rules/`、`engine/scripts/` 等） | 走**贡献流程 PR**：在 framework 仓库改源 → 跑 sync 脚本重生成适配层 → 提交 PR 回流上游 | 改动进入上游版本库，升级不再冲突、不再被覆盖 |
| 改个人规则 / 偏好（语言、知识优先、场景规则等） | 放 **`personal/` 覆盖层**（个人实例数据，gitignored，升级不覆盖） | 实例级差异不污染通用层，升级零冲突 |
| 改个人引擎行为（hooks / 权限等） | 改 **`.claude/settings.json`** 等 settings 类个人配置 | 个人配置默认不提交，不提交则不随升级覆盖，且为各引擎原生入口 |
| 改生成的适配层（`.claude/skills/kb-*` 等） | 不改产物，改对应 `core/` 能力源后再跑 sync 重新生成 | 产物由 sync 整体重建，手改即刻失效 |

## 速查表

| 路径 | 可改 / 只读 | 为什么 |
|---|---|---|
| `personal/` | 可改 | 私有数据层，gitignored，升级不覆盖 |
| `.claude/settings.json` · `settings.local.json` | 可改 | 个人配置默认不提交（`.local` 已被 gitignore 排除），不提交则不随升级覆盖 |
| `framework/core/`（能力源） | 只读 | 机制唯一事实源，升级覆盖；要改走贡献 PR |
| `framework/ops/`（含 rules/） | 只读 | 通用规则资产，升级覆盖；要改走贡献 PR |
| `framework/engine/`（含 scripts/） | 只读 | 通用引擎，升级覆盖；要改走贡献 PR |
| `framework/docs/` · `knowledge/` · `samples/` | 只读 | 通用资产，升级覆盖 |
| `framework/AGENT.md` · `index.md` · `activation.md` | 只读 | 契约 / 导航 / 入口注册表，升级覆盖 |
| `.claude/skills/kb-*` 等适配层 | 只读 | sync 生成产物，升级重建；要改改 `core/` 源 |
| `framework/` 其它未列出文件 | 只读 | 默认只读：framework 层非 settings 类默认不可改 |
