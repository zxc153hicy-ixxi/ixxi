# 错误码规范

> 目的：让用户遇错可自查（智谱风险 5.5「用户遇错可自查」）。所有脚本出错时输出**错误码四要素**，不裸报 traceback；错误码登记于本文档，供检索与复核。

## 一句话定位

**错误码是脚本与用户之间的「可检索问题编号」** —— 出错时输出 `IXXI-E<3位数字>` + 人类可读解释 + 修复建议 + 相关文档链接，用户按码自查、按建议处置，不再面对一堆裸 traceback 无从下手。

## 一、错误码格式

- 统一格式：`IXXI-E<3位数字>`，如 `IXXI-E001`。
- 按类别分段（数字段固定，不跨段使用）：

| 段 | 类别 | 使用范围 | 示例 |
|:--:|------|----------|------|
| E0xx | 通用 | 参数/用法、数据文件缺失或损坏、IO/编码 | IXXI-E001 / E010 |
| E1xx | 入库 | Ingest 源文件、frontmatter 冲突、入库目标写入 | IXXI-E101 / E110 |
| E2xx | 体检 | Lint/健康度检查项失败、健康度预警 | IXXI-E201 / E220 |
| E3xx | 同步 | git sync/push 失败、冲突未解决 | IXXI-E301 / E310 |
| E4xx | 迁移 | 迁移前置校验、迁移目标已存在 | IXXI-E401 |
| E5xx | 安全 | 个人数据阻断、敏感信息检出 | IXXI-E501 / E510 |

## 二、错误四要素

每个错误码固定携带**四要素**，缺一不可：

1. **错误码** —— 唯一编号，如 `IXXI-E501`。
2. **人类可读解释** —— 一句话说清「发生了什么」（中文，用词对非开发者友好）。
3. **修复建议** —— 用户可直接照做的处置步骤（不空谈）。
4. **相关文档链接** —— 指向仓库内可查证/可执行的文档路径。

## 三、接入规则（脚本侧）

脚本出错时按以下统一格式输出（stdout 正常日志；**错误走 stderr**）：

```
IXXI-E501 | 个人数据阻断：检测到 personal/ 目录含内容，且存在非本地（可能公开）remote
修复：将个人数据保留本地，删除或更换公开 remote 后重试
参考：framework/ops/rules/personal隔离规范.md
```

强制要求：

1. **不裸报 traceback**：顶层用 try/except 捕获，出错时输出四要素后按退出码退出；调试信息（如原始异常）可追加在 `参考` 之后，不得代替四要素。
2. **退出码约定**：`0`=正常放行；`2`=业务性阻断/检查未通过；`1`=执行错误（配置/环境/数据损坏等，配合错误码输出）。
3. **新错误码先登记后使用**：任何脚本引入新错误码前，必须先在本文件「错误码总表」登记（防重复、防撞号），lint 复核时检查总表与脚本引用一致性。
4. **语言边界**：解释/建议用中文，错误码、文件路径、技术标识符保留原文（G6）。
5. **非致命异常**（有兜底可继续跑）：错误码照常输出到 stderr，同时继续兜底流程，不中断任务。

## 六、登记规则（新码流程）

1. **分配**：按上文分段表选取可用编号（本段内顺延，避免已用号）。
2. **登记**：在「错误码总表」追加一行（四要素齐全）。
3. **接入**：脚本顶层捕获异常，按「三、接入规则」输出四要素。
4. **复核**：lint 时 grep 脚本内 `IXXI-E\d{3}` 与总表比对，发现未登记/重复 → 告警。
